キャラクター発話API

「キャラクターを使う」で音声エンジンと背景を選び、「AI・外部アプリで話す」を押してください。開いたウィンドウで発話の受付をオンにし、「AIへの指示サンプル」の文章をコピーして、ローカルアプリを操作できるAIに渡してください。接続先と操作手順も一緒にコピーされます。起動元の画面は閉じても使えます。APIの接続先は固定で、セッションIDは不要です。

GET /api/runtime/status で状態を取得します。accepting・connected・ready がすべて true のときだけ送信してください。state は closed / starting / idle / synthesizing / speaking / stopping / error。character はキャラクター名、current.id は現在の発話IDです。

新しく開いたキャラクターが接続先になります。別のウィンドウの受付をオンにすると、そちらに切り替わります。同時に受付するのは1体だけです。閉じても以前のウィンドウへ自動で切り替わりません。受付オフは新規の発話を拒否します。受理済みの発話は継続します。

待機中に話す

POST /api/runtime/speech

{"request_id":"新しい一意なID","action":"speak","text":"こんにちは。"}

AIが必要と判断したときだけ割り込む

{"request_id":"別の一意なID","action":"replace","expected_utterance_id":"確認したcurrent.id","text":"訂正します。こちらでした。"}

停止だけなら action を stop にし、text を省略します。発話が変わっていた場合や停止処理中は409を返します。状態を再確認してください。replace は停止確認後に次の音声生成・再生を始めます。古い生成結果は再生しません。エンジン内部の生成計算そのものの中止は保証しません。

202は受付完了です。発話完了ではありません。GET /api/runtime/speech/{request_id} で結果を確認してください。completed は完了、failed / interrupted は失敗・中断です。通信結果が不明なら同じ request_id と同じ内容で再送します。接続先が変わっても、保持中の履歴にある発話を重複再生しません。固定APIは最大400件の履歴を保持し、サーバー再起動で消えます。履歴が404になった不明な発話は、自動で再送しないでください。

発話は最大2000文字で、エンジンへは200文字以下に分割して渡します。409は受付オフ・未接続・発話中・対象発話の変更などです。状態を確認してから次の操作を判断してください。

Codex用スキル・プログラムからの利用

Codex用スキルZIPを展開し、svg-through-speakフォルダをCodexのskillsフォルダに配置してください。スキルの内容も確認できます。発話クライアントは speak.py。Pythonの標準ライブラリだけで使用できます。

python speak.py --url http://127.0.0.1:8765 status
python speak.py --url http://127.0.0.1:8765 speak --text "こんにちは。"
python speak.py --url http://127.0.0.1:8765 result --request-id 返されたrequest_id

別のプログラムからも同じJSON APIを直接呼べます。TTSの選択、受付のオン、ウィンドウの起動は利用者が画面で行います。

const root = 'http://127.0.0.1:8765/api/runtime';
const state = await (await fetch(root + '/status')).json();
if (state.accepting && state.connected && state.ready && state.state === 'idle') {
  const requestId = crypto.randomUUID(); // 応答不明時もこのIDと本文を再使用
  const response = await fetch(root + '/speech', {
    method: 'POST', headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({request_id: requestId, action: 'speak', text: 'こんにちは。'})
  });
  console.log(response.status, await response.json());
}

JavaScript例はNode.jsまたは同じオリジンからの利用向けです。任意の外部Webページに書き込み権限を開放するAPIではありません。

状態通知・表示

同じオリジンから /api/runtime/sessions/{session_id}/socket/display にWebSocket接続すると status と pose 通知を受信できます。type: heartbeat を2秒ごとに送ってください。操作はREST APIから行います。切断・再接続で発話を自動再開しません。

status の caption は再生中のセリフ全文です。それ以外は空文字。字幕の描画・背景・フォントや文字単位のタイミング情報は含みません。ゲームなど利用側で表示してください。speaking はプレイヤーでの再生状態であり、OSのミュート状態は判定しません。

/web/player.html?session={session_id}&display=1 は透過の表示専用ページです。音声は出力ウィンドウから一度だけ再生します。OBSなどでは表示URLとアプリの音声を取り込んでください。出力ウィンドウが切断すると口を閉じて待機します。

マイク・カメラで使う

起動前の画面で「マイクで動かす」または「カメラで動かす」を選びます。入力機器や反応する音の大きさ、目の左右などは開いたウィンドウで設定し、開始ボタンを押してブラウザの使用許可を確認してください。許可できない場合は、その出力ウィンドウのURLをChrome／Edgeで開き直してください。権限をアプリが自動変更することはありません。

マイク入力と顔解析は出力ウィンドウの中で行います。起動元の画面は閉じて構いません。出力を閉じると入力も停止します。映像やマイク音を外部へ送信せず、マイク音は再生しません。音声を収録する場合は取り込み側でもマイクを指定してください。マイク・カメラで開いた場合、APIの発話受付はオフです。

設定を隠す・背景

「設定を隠す」を押すとキャラクターだけ表示します。Escキーで設定を再表示できます。表示専用URLには設定パネルが表示されません。

背景は起動前の画面で、緑・青・任意のクロマキー色、または透過を選べます。普通のブラウザウィンドウはデスクトップまで透けないため、ウィンドウ取り込みではクロマキーを使ってください。表示専用URLは透過です。素材そのものに描かれた背景色は、背景設定だけでは消えません。
