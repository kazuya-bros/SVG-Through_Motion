# SVG-Through Motion

## v0.1.0-preview

元絵とSee-Throughで分割したPSDから、立ち絵をSVG化して動かすWindows向けの技術プレビューです。

- 目・口の補正、瞬き、口パク、顔向き、髪・耳・翼・服・小物の揺れ
- SVGならではの色変更、ライティング、線・色の出現、通信中などの演出
- 配信向けの表示ウィンドウ、ホットキー、透過WebM／MP4保存
- 中央ドラッグによるプレビュー移動、ホイールズーム、PSDレイヤーの支点調整

この公開版は展示会と動作確認のための**テスト用プレビュー**です。素材や環境によって変換時間・描画負荷・仕上がりに差があり、一般的なPSDでの安定動作やすべての動画プレイヤーでの再生を保証しません。まずは同梱サンプル、または元絵と同じキャンバスのSee-Through PSDで試してください。

製品はGitHubの **Releases** からWindows用ZIPをダウンロードできます。ソースからの起動は下の「起動」を参照してください。

## AIエージェントからの操作（2026-09-15）

素材登録・レイヤー補正・Depth・SVG変換・編集・出力・発話・表情・演出を、APIと同梱MCPから操作できます。53操作の一覧と引数、接続状態、進捗・結果、確認画像を取得できます。[接続設定と対応範囲](docs/agent-control.md)を参照してください。ウィンドウ起動、カメラ等の初回許可、画面専用の一部設定はUI / Computer Useで行います。

出力画面の「AIと演出」で、外部で作った画像の登録・配置、字幕のサイズ・色・書体、表情と動きを組み合わせた演技プリセットを扱えます。通常設定を保ち、AIが作った演技を再生・保存・解除できます。MCPから画像と字幕を合成した実画面も取得できます。[使い方と演技レシピ](docs/stage-performance.md)。

出力画面の「演出」で、サラサラ消える・粒から現れる・通信中・幸せの光を切り替えられます。強さ・時間・発話終了時に戻す設定があり、配信ソフトの表示にも反映します。[演出の操作とAPI](docs/character-effects.md)。

## パーツ準備を統合（2026-09-15）

メインメニューの「パーツを準備・補正する」から、PSDまたは一枚絵を開きます。

1. See-Throughで分割を試し、Seedごとの候補から採用します。再生成は非表示の候補を追加し、ロックした採用パーツを保ちます。
2. 重なり・位置・大きさ・透明度・役割を補正します。透過画像の追加、範囲の切り出し、補修先への合成にも対応します。
3. 「保存」で続きから再開できます。「補正PSDを保存」ではPSDと設定、および再開用の作業ZIPを取得できます。
4. 「SVG編集へ進む」で、補正済みパーツをSVG化します。必要なDepthは補正後の形から生成し、追従先・奥行きとともに引き継ぎます。自動生成はオフにもできます。

分割・DepthはPachiPakuGenの準備済みSee-Through環境を自動検出します。別の場所なら環境変数 `SVG_THROUGH_SEE_THROUGH_ROOT` にランタイムのルートを指定してください。対応版は `e4cb250dc69defe6f982168dab684aa461552b5b`。モデルと実行環境の自動ダウンロード・初期構築は今回含みません。環境がなくてもPSD補正とSVG編集は使えます。

「範囲から補正する」は画像・マスク・参照絵・依頼文のZIPを作ります。外部ツールで得た透過PNGを追加し、位置と補修先を指定して戻せます。アプリから外部AIへ自動送信する機能ではありません。

新規の補正素材はSVG描画が標準です。線と塗りを編集して動かせます。塗りの変換結果が気になる場合は、未編集の固定パーツだけ元PNGを選択できます。既存プロジェクトの描画設定は維持します。

「動きをつける → 表情・確認」に表情プリセットと動作確認の一巡を追加しました。表情はプロジェクトに保存され、出力ウィンドウでも数字キー1〜9で切替、Shift併用で押している間だけ切り替えます。ショートカットはそのウィンドウにフォーカスがあるときに有効です。口パクは表情切替中も入力に追従します。

素材補正は最大100レイヤー、1画像16メガピクセル、入力ファイル100MBまで。外した候補の画像と保存版は作業フォルダに残ります。作業ZIPには現在の素材を含み、全履歴と生成ログは含みません。See-Through再実行・Depth推定の品質は入力や設定に依存します。

詳細と検証結果: [統合ロードマップ](docs/integration-roadmap.md)、[統合の検証記録](docs/material-integration-verification.md)。

## カメラで顔向きを動かす（2026-09-15）

「キャラクターを使う → カメラで動かす」で、左右の瞬き・口の開きに加え、顔の左右・上下・首の傾きを控えめに反映します。素材の動き設定が有効な場合に顔向きが動きます。開始時に最初に検出した姿勢を正面の基準とし、「今の姿勢を正面にする」で合わせ直せます。

「顔向きの追従」は初期値50%。0%では顔向きを固定します。「視線・眉の追従」は別の強さで調整し、0%で止められます。顔向きの左右反転は、目の左右入れ替えと独立しています。素材に設定した上下の向きは基準に残し、カメラ追従中は自動の首振り・うなずきを重ねません。髪揺れ・呼吸は維持します。音声再生中の口は引き続き音声を優先します。

映像の解析はブラウザ内で行い、表示専用URLへは動きの値を送ります。実装検証には模擬カメラ入力を使用しており、実カメラによる姿勢精度・使用感は未確認です。

## 現在の書き出し（2026-09-19）

「03 保存」画面には「動画を保存」（透過WebM・白背景MP4）と「プロジェクトを保存して完了」を表示します。描画設定・PNG連番・SpriTalk連携は非表示です。ゲーム専用出力・スプライトシート・PNGパーツ・MPNG・静止PNGも画面から外しています。単体SVG出力はありません。

動画とPNG連番は設定した動きを保存する用途です。後から別のセリフに口パクを自動同期する素材ではありません。PNG連番は透過画像と再生情報のanimation.jsonをZIPにまとめます。従来のエージェント用出力APIは互換性のため維持します。

SpriTalk用ZIPは絵・差分・支点・リグ・動きの設定を保持しますが、SpriTalk側の専用インポーターと共通ランタイム組み込みは未対応です。[連携仕様](docs/spritalk-integration-spec.md)と[開発担当へ渡す依頼文](docs/spritalk-handoff.md)を参照してください。以下の過去のUI・書き出し説明より、この節を優先します。

**分けたイラストに、まばたきと動きを。** 元絵とSee-Throughで分割したPSDから、目・口を整えて動くキャラクターを作るローカルアプリです。

作成フローは「形を整える → 動きをつける」の2工程。動きができたら、画像・動画・ゲーム素材に書き出すか、「キャラクターを使う」から独立した表示ウィンドウを開けます。動画用の音声合わせは任意です。独立した出力ウィンドウでは字幕・画像・感情の演出も利用できます。

用意するものは、**両目と口が開いた元絵（PNG・JPG・WebP）と、その絵をSee-Throughで分割したPSD**です。同じキャンバスサイズ・位置で用意してください。読み込みは3ステップです。STEP 1で「1枚絵とPSDだけで始める／差分PSDも使う」、STEP 2で必要なファイル、STEP 3でSVGの仕上がりを選びます。専門的な変換設定は折りたたみ、手動／AIの選択は最後の開始ボタンの前にあります。手動で始めても途中からAIに依頼できます。

通常素材に対応する**Depth PSDも任意で追加**できます。顔と前後の髪・頭飾りの動きに奥行きの差を付け、閉じ目・閉じ口には通常素材のDepthを共用します。取り込み後の「顔・瞳」で補助のオン・オフと強さを調整でき、Depth情報はプロジェクトに保存されます。[入力条件と反映範囲](docs/depth-import.md)を参照してください。

開始画面にはTeth2の元絵・PSD内部のパーツ例・動く完成例があります。「自分の素材で作る」を押すと素材登録の画面に切り替わり、「最初の画面に戻る」で入口に戻れます。「Teth2で試す」は準備済みのサンプルを独立したIDのコピーとして開きます。編集結果は「保存」で持ち運べるJSONに保存でき、サンプル原本には反映されません。動くプレビューに音声はなく、動きを減らすOS設定に対応します。

AIへ渡す場合は目・口と動きまでが対象で、TTS・声の選択と出力の起動は自分で行います。以下の旧サンプルや描き足し方式の説明は過去の試作記録です。[AI補正の初期仕様と検証範囲](docs/ai-assist-p0.md)

## 起動

`Start-Studio.cmd` をダブルクリックし、[http://127.0.0.1:8765](http://127.0.0.1:8765) をChrome / Edgeで開きます。現在のPCでは `I:\python\python.exe` のインストール済みライブラリを利用します。終了は起動したコンソールで Ctrl+C。

```powershell
cd E:\SVG化
.\Start-Studio.ps1
# 別のポートやPythonを使う場合
.\Start-Studio.ps1 -Port 8766 -Python 'I:\python\python.exe'
```

別環境に移す場合はPython 3.10以上で `requirements.txt` の依存を用意してください。フロントエンドのビルド・npm installは不要です。カメラ初回起動だけはMediaPipe JS/WASMとモデルを公式配布先から取得するためネット接続が必要です。

### 200 OKなのに画面が開かない場合

サーバーのアクセスログの200は応答開始を表し、ブラウザが本文を受信できた保証ではありません。2026-09-07、このPCではHTTPヘッダーだけ届き本文がタイムアウトする現象を確認しました。標準の最小HTTPサーバーでも再現し、通常のバイナリTCP通信は正常でした。ESET Internet Security 19.2.7.0のWebアクセス保護など、HTTPを検査する層との干渉が候補です。ESETが原因かどうかは一時停止との比較が必要で、断定していません。

更新した起動処理は、内部の起動完了後に本文まで1回確認し、失敗理由を表示します。起動確認100回の連続リクエストは廃止しました。使用中ポートで本文が取得できない場合は二重起動しません。変更は次回の `Start-Studio.cmd` 起動から有効です。

接続確認は `http://127.0.0.1:8765/api/health` がJSONを表示するかで行えます。ESETの設定で切り分ける場合は「Webアクセス保護」のみを一時停止してこのURLを確認し、確認後すぐに有効へ戻してください。設定変更は自動では行いません。公式の[Webアクセス保護の説明](https://help.eset.com/eis/19/en-US/idh_config_web_basic.html)に機能と互換性対策が記載されています。

## 使い方

### 新しいワークスペース（SVG-Through Motion）

アプリ名を **SVG-Through Motion** に変更しました。作成フローは上部の「01 形を整える → 02 動きをつける」の2工程です。書き出しと動画用の音声は「動きをつける」から任意で開きます。配信用の操作はヘッダーの「キャラクターを使う」から別画面へ切り替え、「作成に戻る」で元の作業へ戻れます。「形を整える」では左側にレイヤー一覧を常時表示し、選択したパーツを編集できます。他の工程では左欄を畳み、プレビューを広く表示します。

| 作業 | 操作できること |
|---|---|
| 形を整える | 上のタブで目・口、左のレイヤー一覧でその他のパーツを調整。目・口は画面上でドラッグし、数値は微調整に使用 |
| 動きをつける | 待機などのプリセット、頭・身体、髪・腕、弾みの調整 |
| 音声を合わせる（任意） | 動かす画面から開き、動画用の音声や口パクを調整 |
| 配信（作成とは別画面） | 配信設定・マイク・カメラのタブ。OBS、外部連携、リアルタイム入力 |
| 書き出す | 画像・動画、またはゲーム用のPNG連番・スプライトシート |

通常起動では、編集画面の前に「新しく作る／保存済みから再開」のスタート画面を表示します。最後の変換結果を勝手に開く処理は廃止しました。新規作成は元画像＋対応PSDを最初に登録し、読み込み後は目→口の順に調整へ案内します。編集画面には登録フォームを常設せず、別の素材へ切り替える場合だけ上部の「別の素材を開く」を使います。

「保存」で調整をJSONへ保存します。次回はスタート画面の「保存済みから再開」でJSONを選んでください。変換結果の一覧は読み込み時点の素材なので、編集の続きには保存JSONを使います。旧画面を開いたままの場合は、先に編集内容を保存してから再読み込みしてください。既存JSON・API・出力ファイル名は互換性のため維持しています。

レイヤー選択だけでは描画を再構築しません。役割変更やSVG差し替えなど、実際に素材が変わる操作では再構築します。作業エリア上の直接変形は、閉じ目・口の形と髪の房のガイドに対応しています。パーツ全体の位置などはレイヤーを選んで設定欄から調整します。

### 独立したキャラクター出力（2026-09-10）

開始画面の「目・口と動きをAIに任せる」は、元画像＋対応PSDの変換から目・口の補正、動きの調整までが対象です。依頼を外部AIへ渡すと、動きも候補内で調整・比較し、完了時にまとめて反映して「動きをつける」画面へ戻ります。「これでOK」「もう一回頼む」「AIに頼む前に戻す」で確認できます。TTSエンジン・声・音声設定と、発話・出力ウィンドウの起動・書き出しはユーザーが行います。

「キャラクターを使う」でTTSエンジンと声を選び、「出力ウィンドウを開く」。キャラクターだけの別ウィンドウがAIの発話を受け付けます。編集画面を閉じても、ローカルサーバーと出力ウィンドウが動いていれば継続します。声と素材は起動時に固定し、変更時は出力を閉じて開き直します。音声の自動再生が制限される環境では、出力側の「音声を有効にする」を押してください。

AI用の接続情報と透過表示専用URLは出力設定からコピーできます。発話APIは `/api/runtime/sessions/{session_id}/speech`。状態確認後に `speak`、割り込み時は現在の発話IDを指定して `replace`、停止だけなら `stop`。同じrequest_idの再送は直近100件の履歴内で重複再生を防ぎます。202は受付であり、完了は結果APIまたはWebSocketの状態通知で確認します。最大2000文字を短く区切って読み上げ、切断後の自動再開はしません。セッションは最大4つ、サーバー再起動で消えます。

再生中のセリフは `caption` として取得できます。字幕の背景・フォント編集や文字単位のタイミング情報は含めず、ゲーム等の表示側で扱います。表示専用URLは音を再生せず、音声は出力ウィンドウのアプリから取得します。[発話APIの使い方](http://127.0.0.1:8765/web/runtime-help.html)

### 編集画面のAI操作・OBS・素材出力（従来の連携）

このアプリ単体で使う3つの出口を追加しました。PachiPakuGenへの組み込みやSpriTalkのインストールは不要です。

| 出口 | 今回の実装 | 使うために必要なもの |
|---|---|---|
| AIから操作 | ローカルREST API、OpenAPI、Pythonクライアント。再生・時刻・口/目・動きの設定・選択した声での発話・プロジェクト読込/保存・素材出力 | 素材を開いた編集画面で「AI・OBS接続を開始」。ローカルTTSでの発話には音声エンジンの起動と声の選択が必要 |
| OBSへ表示 | 背景透過のブラウザソース、編集画面のポーズ同期、マイク音量による口パク | OBSに画面内のURLを指定。編集画面を開いたまま維持。音声はブラウザ音声またはマイクをOBSで別途取得 |
| ゲーム・動画素材 | 透過PNG連番ZIP、複数ページ対応スプライトシートZIP、fps/矩形/再生時間を記録したanimation.json | 「ゲーム・動画用の透過素材」で長さ・fps・サイズを指定 |

従来の連携は「キャラクターを使う」内の「編集画面の動きをそのまま送る（マイク・カメラ）」にあります。OBS用の標準URLは `http://127.0.0.1:8765/web/obs.html`、操作仕様は [編集用API・OBS・素材出力の説明](http://127.0.0.1:8765/web/control-help.html) と [API仕様](http://127.0.0.1:8765/api/docs) を参照してください。

AIクライアントは `python tools/studio_control.py status`、`python tools/studio_control.py command @command.json` で使えます。JSON例は上記説明にあります。MCPサーバーは未実装で、HTTPまたはシェルを呼び出せるAI向けです。操作の受付と完了は別々に確認でき、自動再送はしません。

素材ZIPは動きの設定を固定fpsで描画します。音声・マイク・カメラ・確認用ポーズは含みません。最大600コマ、透過背景、拡大/トリミングなし。出力は従来どおり新しいIDのフォルダに保存します。PNG連番とシートの実出力は確認済みですが、OBS本体での表示と実マイク・実SBV2を通した今回の連携は未確認です。詳細は [検証記録](VERIFICATION.md) にあります。

### 目・口の追加PSD（任意）

最初の読み込み画面で「基本素材から作る」を選ぶと、閉じ目・閉じ口の下書きを自動生成し、目→口の順に画面で整えます。「用意した差分を使う」では、目・口それぞれにPSDを使うか、下書きを調整するかを選びます。閉じ目のPSDに閉じ口も入っていれば「閉じ目と同じPSDを使う」で共用できます。母音PSDは「母音の口も追加する（任意）」にまとめ、必要なものだけ指定します。基本モードへ戻した場合は、以前選んだ追加PSDを送信しません。

差分を使った部位は「開閉を確認」から始まり、調整欄・画面ハンドルを省略します。手動スライダーで確認し、必要な場合だけ「位置・大きさを調整する」をONにします。差分のない部位は従来の直接編集へ案内します。

閉じ目は表示中の `eyelash-r` / `eyelash-l`（まつ毛）、口は `mouth`（口）レイヤーだけをSVG化します。追加PSDの身体・髪などは取り込みません。

ベースは従来どおり、両目と口が開いた元画像＋対応するPSDです。追加PSDは同じキャラクター・同じキャンバスサイズ・位置で用意してください。差分は元座標のまま配置し、ベースの口枠への引き伸ばしや自動位置合わせは行いません。各ファイル100MB以下、100レイヤー・16メガピクセル以下です。

追加した母音はPSD由来の口に切り替わり、未追加の母音はベースの口を使います。追加した閉じ目・閉じ口は自動生成より優先されます。画像として取り込んだ差分は位置・幅・傾きなどで調整でき、生成した線専用のカーブ編集は適用されません。差分はプロジェクトJSON、パーツZIP、アニメーションSVG、Canvasを使う素材・動画出力にも含まれます。

今回の素材セットなら、ベースに `open_a.png` ＋ `open_a.psd`、閉じ目に `close_eye.psd`、閉じ口に `open_eye.psd`、5母音に各 `open_a / open_i / open-u / open-e / open_o.psd` を指定します。

### 編集の基本

「形を整える」は静止した作業エリアです。最初に目を確認・調整し、「次へ」で口へ進みます。PSDの閉じ形がある部位は確認から、それ以外は直接編集から始まります。標準は **閉じ口／開いた口** の2形です。新規素材の母音変形はOFFで、既存JSONの明示的なON/OFFは保持します。

閉じ目・閉じ口は共通の変形枠で調整します。枠内で移動、8個の四角で拡縮、上の丸で回転。角は縦横比を保ち、Shiftで自由な比率、Altで中心から拡縮します。目のもう片方も画面上で選べます。口角・カーブは「カーブ・線」に切り替え、線の太さなどは折りたたんだ数値欄で微調整します。目の変更は閉じ目の画像だけを更新し、全パーツの描画準備を繰り返しません。

初期表示は開き目・開き口です。「閉じ目を確認する／閉じ口を確認する」で完全に閉じた形へ進みます。PSD差分があれば確認を基本とし、必要な場合だけ調整をONにします。「開く／閉じる／重ねて調整」と手動スライダーで開閉を確認できます。重ね表示は任意で、目78%・口11%を使います。

閉じ口は元の開口の輪郭から推定した線を使い、両端を細くして元絵の色になじませます。左右の丸をドラッグすると口角の高さと幅、中央の丸でカーブ、枠で位置を変更できます。細かな線の太さ・色・端の細さは「数値・線・歯の詳細」にあります。これは本アプリが生成する線形状が対象で、複雑な差分SVGを新しい輪郭に描き替える処理ではありません。

「開いた口」は元絵を基準に幅・開き・位置・傾きを調整します。無音付近は口内を表示せず、歯や口内が細い筋として残るのを抑えます。「母音で形を変える（オマケ）」を有効にした場合だけ、あいうえおの個別調整と読みがなの指定が現れます。母音別の別画像を生成する機能ではありません。

「表示」で口元・顔全体・全身を切り替えられます。矢印キーは位置の微調整、Shift併用で大きく移動。「元に戻す」またはCtrl+Zでドラッグ1回分を取り消し、Ctrl+Shift+Zでやり直せます。Escはドラッグ中ならその操作を取り消し、通常時なら編集を終えます。

形の調整中は、呼吸・揺れ・自動瞬き・音声やカメラの動きをプレビューへ反映せず、目と口の手動スライダーだけで開閉を確認します。無操作中は全体を再描画せず、再生バーも表示しません。「動きをつける」でアニメーションの確認へ進みます。

作業エリアはホイールでカーソル位置を保って拡大縮小し、空いているところをドラッグすると表示位置を移動できます。「全体」で表示を戻します。目の工程では顔付近を自動で拡大します。

パーツ調整は任意です。「形を整える」の左側にあるレイヤー一覧から選ぶと、役割・位置などの設定を表示します。行を上下にドラッグして青い挿入線の位置で離すと、重なり順を変更できます。上が手前、下が奥です。一覧の端では自動スクロールし、Escまたは一覧の外で離すとキャンセルします。選択行でAlt＋↑↓を押して一段ずつ移動することもできます。

口の直接編集中は背景を一度準備して口のSVGだけを更新します。調整ごとの全パーツの再描画準備を廃止し、全体プレビューの更新は編集終了時にまとめます。初回の背景準備と終了時の全体更新には従来の描画時間がかかります。調整はプロジェクト内に反映されますが、ファイル保存には上部の「保存」を使ってください。

1. 「元画像＋PSDの顔で開く」で銀髪サンプルを変換します。別素材は「自分の元画像＋PSDを読み込む」で同じサイズ・位置の元画像とPSDを選択します。全PSD方式は「全レイヤーをPSDから開く」、一枚絵は従来の読込欄を使います。出力先は毎回新規です。
2. 「比較」でSVGと元画像を見比べます。全PSD方式の場合のみ、比較元はPSDレイヤーの再合成画像です。
3. 左のレイヤーを選ぶと、役割・X/Y・不透明度・重なり順を調整できます。上が手前です。r/lはキャラクター自身の右/左で、トラッキング側と異なる場合は左右を入れ替えます。
4. 「動き」で揺れ・呼吸・瞬き・口パク・ループ長を設定します。タイムラインを動かすと停止して任意の時刻を確認できます。「表情を確認」の口スライダーはプレビュー専用で、ループSVGには「ループで口パク」の設定を使います。
5. 「プロジェクト保存」はSVG本体と元画像も含むJSONを保存します。保存したJSONは「保存したプロジェクトを復元」から読み込みます。画面の編集は自動保存されません。再起動時は最新の変換結果が開きます。

## 元画像＋PSDの顔、頭・顔・髪の変形

「腕・前髪・後ろ髪も分離」を有効にして読み込むと、動かすパーツはPSDの分離済みの絵を優先します。元絵では隠れていた肩・袖・髪などの補完部分も残します。胴体や顔の下地は元絵を基準に組み立てます。袖と胴体の前後関係はPSDの重なりから判定します。

読み込み後、左のレイヤー一覧にある「パーツの絵を確認」で、気になるパーツだけ「PSDのパーツ／元絵の切り抜き」を同じ範囲で比較し、切り替えられます。元絵の切り抜きには隠れた部分の補完がないため、動かすと隙間が出ることがあります。選択と両方の候補はプロジェクトJSONに保存され、次回も変更できます。この比較機能は新しく読み込んだ素材と更新済みTeth2サンプルが対象です。過去の保存済み素材を自動で置き換えることはありません。サーバーの更新後は再起動してから新しく読み込んでください。

Teth2では袖・髪・頭飾りをPSD優先とし、サンプル用の目・口の調整や耳の表示設定は別に保存しています。分離チェックを外した素材では、従来の一枚の下地として組み立てます。

「頭・顔・髪の立体的な動き」で頭の傾き、顔の左右向き、うなずき、身体の遅れた追従、毛先の曲がり、首の支点を調整できます。頭と身体の間を連続的に変形し、目・眉・口の位置と横幅、顔の輪郭を小さく変えます。独立した眼鏡パーツには「眼鏡」の役割を指定できます。髪はPSDの領域に限定して根元から毛先へ大きく遅れて曲がります。

既定は「形を保つ・PachiPakuGen参考」です。「控えめな揺れに整える」で頭1.2°、小さな視差・うなずき、二重バネの設定にできます。顔と胴体はそれぞれ固定支点の回転と移動で形を保ち、首の接続部だけを補間します。分離していない素材の髪は顔と服の中央を保護し、選択した波または二重バネで側面の毛先を動かします。局所変位は1024px幅で最大6pxです。以前の輪郭や幅の変形は分離していない素材で「柔らかい変形・従来」を選べます。

PachiPakuGenで採用済みのAnime2.5DRig（852話氏）の二重バネと、PuruPuruPNGTuber（ろてじん氏）の波・位相設計を適応しています。ループの途中へ移動しても同じ結果になるよう、バネは周期定常応答を計算します。ランダムな目線、髪房の自動検出、上流アプリ全体の移植は含みません。出所と変更点は [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) に記録しています。

プレビューと動画はSVGを一度描画してからメッシュで変形します。SVG出力には外部画像を含まず、必要なベクターパスだけを区画ごとに参照するSMILアニメーションを格納します。設定・首の支点・髪の領域・開口差分はプロジェクトJSONに保存されます。

小さな角度の表現向けです。横顔や隠れている面は生成しません。肌の下地と前髪の境界はPSDの分解精度に依存するので、閉眼時も比較して確認してください。胸・耳の独立した揺れは従来の分離パーツ方式で、ハイブリッドの身体全体を胸パーツに割り当てないでください。

## 過去のアニメーション調整を使う

[一回弾みのMP4](examples/sns-single-20260906-172720/single-bounce.mp4) / [SVG](examples/sns-single-20260906-172720/single-bounce.svg) / [復元用JSON](examples/sns-single-20260906-172720/single-bounce.project.json) を保存しています。この過去の動画例は閉じ口です。現在のアプリの銀髪サンプルには、専用に生成してSVG化した開口差分を追加しています。独立していない胸部は動かしていません。

「SNS・一回弾み」を選ぶと、3秒に一度の弾み、間、髪・胸・耳の遅れ、瞬き、口パクをまとめて設定できます。白背景・文字なしが既定です。弾む高さ、髪・耳の角度、胸の追従量、閉じ口幅は個別に調整できます。

髪は根元、耳は下側を既定の支点にします。左のパーツを選び、役割を「髪」「胸・衣服の胸部」「右耳」「左耳」に割り当て、支点と揺れ倍率を必要に応じて調整します。胸は独立した胸部パーツを用意してください。服全体に割り当てると服全体が動きます。既存の変換済みプロジェクトは役割を保持するため、耳などの新しい役割は手動で設定してください。

閉眼の最後に白目・瞳を完全に非表示にし、残った白い縁を防ぎます。閉じ目線は専用差分SVGに交換可能です。参照会話の採用判断と実装上の違いは [animation-decisions.md](docs/animation-decisions.md) に記録しています。

## 読み上げる声を選ぶ

「声と表情」でエンジンを選択し、「接続して声を取得」→声を選択→セリフを入力→「生成して話す」で確認します。接続URLは「接続・音声の詳細」にあります。テキストは200文字までです。

| エンジン | 初期接続先 | 必要なもの |
| --- | --- | --- |
| Style-Bert-VITS2 | `http://127.0.0.1:5002` | `server_fastapi.py` と音声モデル |
| VOICEVOX | `http://127.0.0.1:50021` | 起動したVOICEVOXエンジン |
| AivisSpeech | `http://127.0.0.1:10101` | 起動したAivisSpeechエンジンと音声モデル |
| Irodori-TTS（OpenAI互換） | `http://127.0.0.1:8088` | Aratako版Irodori-TTS-Serverと登録した声 |
| ブラウザ標準 | 接続設定なし | ブラウザで利用可能な日本語音声 |

ローカル音声エンジンは別途インストール・起動してください。既存のモデル・設定は変更しません。接続先はHTTPのloopbackアドレスのみです。SBV2の5002はこのPCの設定に合わせた初期値なので、各自のサーバーに合わせて変更してください。

VOICEVOXとAivisSpeechは声の名前・スタイルから選択できます。Irodori-TTSは [Aratako版のOpenAI互換API](https://github.com/Aratako/Irodori-TTS-Server)（`/v1/models`、`/v1/audio/voices`、`/v1/audio/speech`）に対応します。別方式のWebUIは対象外です。URL末尾の `/v1` はあってもなくても構いません。認証が必要な場合だけ詳細欄にAPIキーを入力します。

エンジン・声・接続先はプロジェクトJSONに保存され、再開時に復元します。APIキーは保存しません。外部AIの `speak` も、この画面で選択した声を使います。エンジンごとにAI側の送信形式を変える必要はありません。

ローカルTTSの返すWAVを再生し、波形の音量に同期して口を開閉します。WAV保存・動画への音声収録も可能です。ブラウザ標準音声は波形を取得できないため簡易口パクで、WAV保存やWebM/MP4への音声収録には対応しません。どちらもAI操作は発話終了まで待ちます。WAV/MP3等の音声ファイルも入力できます。

接続仕様は [VOICEVOX Engine](https://github.com/VOICEVOX/voicevox_engine)、[AivisSpeech Engine](https://github.com/Aivis-Project/AivisSpeech-Engine) を参照しています。音声モデルの権利・利用条件は各モデルに従ってください。

## 顔トラッキング

「顔トラッキング」→「カメラを開始」で、ブラウザのカメラ許可を与えます。MediaPipe Face Landmarkerの `eyeBlinkLeft` / `eyeBlinkRight` / `jawOpen` を利用します。左右独立の瞬き、口の開き、平滑化、顔を見失ったときのニュートラル復帰、カメラ停止に対応しています。

映像はブラウザ内で処理します。サーバーへ送信しません。音声再生と併用した場合、瞬きはカメラ、口は音声を優先します。モデルの推論はCPUで約15回/秒を上限とするため、PC性能によってプレビューの速度が変わります。カメラは停止ボタンまたはページ終了で解放します。

## 書き出し

すべて **`E:\SVG化\data\exports\<新しいID>\`** に保存し、画面下に保存したファイルのリンクを表示します。ブラウザの自動ダウンロード許可は不要です。リンクを押すと追加でダウンロードできます。

| 形式 | 内容 |
|---|---|
| ループSVG | SMILアニメーション。外部JS・画像埋め込み不要。揺れ・呼吸・瞬き・設定した口パクを無限再生。無音。 |
| 静止PNG | 現在のポーズ。元キャンバスサイズ、選んだ白背景または透過。 |
| WebM | プレビューの動きを設定した長さを目安に録画。音声ファイル/ローカルTTS再生中は音声も含める。最大辺768px、24fpsを目標。ブラウザの記録開始・終了タイミングや処理負荷で実時間とフレーム数に差が出る場合あり。カメラ入力も録画に反映。 |
| SNS用MP4 | 白背景・文字なし、1080×1350、H.264/AAC、30fps。無音ループは各コマを描画してローカルFFmpegで結合するため指定時間どおり。音声/ローカルTTS再生中・カメラ使用中はライブ録画してMP4へ変換。 |
| パーツZIP | 編集後のSVGパーツ、差分、座標付きポータブルproject.json、合成SVG、ループSVG。 |
| プロジェクトJSON | 編集状態とSVG・比較用元画像を含む再読込用ファイル。 |

WebMと、音声・カメラを使ったMP4は、ライブ動作の記録なので始点と終点の一致は保証しません。無音ループMP4は固定フレームで書き出します。ベクターのまま継ぎ目のないループにするにはループSVGを使用してください。SVGの再生にはChrome/Edge等のSMIL対応ビューアが必要です。編集ソフトによっては静止画として読み込まれます。

## 変換の改善点と限界

- 配置は `layer.left/top + alphaクロップ位置` を保存し、パーツのローカル座標と分離。重なり順、非表示レイヤー、親の可視状態を保持します。
- 色とアルファを別々にトレースします。SVGの輝度マスクで8段階の透過を表現し、マスク付きpasteでアルファが二重に掛かる問題を避けます。透明領域に近隣の色を拡張して黒い縁を抑えます。
- 256px以下の小パーツは3倍でトレースし、SVGでは元サイズへ戻します。瞳・まつ毛・口の輪郭の粗さを抑えつつ、元の配置を保ちます。
- まつ毛/眉の明るい混入除去は選択式です。明度・小領域フィルタには限界があり、必要な淡い線も消す場合があります。比較して設定を変えて再変換してください。瞳を固定色や四角いパッチで塗りつぶしません。
- 瞳は白目の形でマスクし、目の共通アンカーで縮めます。完全に閉じた目には簡易の閉じ目線を出します。
- 元絵が開口なら口パーツの「口素材の種類」を「元絵は開口」にすると、元の輪郭・口内を保って開閉します。閉じ口幅は既定80%。元絵が閉じ口の場合は開口差分SVGを追加してください。簡易の口内を描くモードは明示的に選んだ試作時のみ有効です。歯・舌の自動補完、あいうえおの音素判定は未実装です。差分は元パーツの枠に合わせます。
- 一枚絵の読み込みは1パーツとしてのベクター化です。自動の意味的パーツ分解は含みません。独立した目・口にはSee-Through等の分割PSDが必要です。
- Photoshopの調整レイヤー、複雑なグループマスク、クリッピンググループ、ブレンドモードの完全再現は非対応です。検出した一部の非対応効果は警告します。元PSDと比較してください。
- SVGは元画像を近似します。低解像度画像に存在しない細部を復元するものではなく、グラデーションも色の領域に分かれます。Cubismのモデル書き出し機能はありません。

## 保存先と構成

元PSD・以前のAntigravityスクリプト・既存SVG出力は変更していません。

```
studio/convert.py   PSD抽出、クリーニング、RGB/アルファのVTracer変換
studio/server.py    ローカルAPI、変換ジョブ、保存、ローカルTTSプロキシ
web/app.js         エディタ、音声、カメラ、書き出し
web/motion.js      共通モーション計算、SVG組み立て、SMIL
web/assets.js      SVG入力検証、ポータブルZIP
data/projects/     変換結果（IDごとに新規作成）
data/uploads/      読み込んだファイルの控え
data/exports/      ユーザー操作による書き出し
qa/                テスト結果・実行ログ
```

画像/PSDは100MB、16メガピクセル、100レイヤーまで。書き出しは200MBまで。変換は1件ずつ、保存先の空きが2GB未満なら新規処理を止めます。失敗した変換や中間PNGも再検証用に保持し、自動削除はしません。ストレージ整理は別途ユーザー判断で行ってください。

## 検証

動画の画質は「プレビュー・動画・PNGの描画」で選択します。推奨の「元パーツの塗りを保つ」は、元画像＋PSD変換の未編集の身体・髪パーツについて、SVG化前のPNGを同じメッシュで動かします。SVGの内容を照合して一致したパーツだけに適用し、差し替え済みSVGや目・口の描画は保持します。保存JSONは画素と照合情報を内包できます。元の変換にアクセスできず照合情報もない場合はSVG描画を使用します。

MP4とWebMは長辺1080pxを基準に最大2倍で描画してから縮小します。WebMは30fpsを目標とするライブ録画・12Mbps、無音ループMP4はPNG中間画像・H.264 CRF17。単体SVGは引き続きベクターを出力するので、色の階調は元のSVG化精度に依存します。PNG中間画像が容量制限を超える場合はループを短くしてください。

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/*.test.mjs
```

サーバー起動後、[実ブラウザ検証](http://127.0.0.1:8765/web/verify.html) でSVGマスク、SMIL、入力検証、実PSDの3表情を確認できます。「MediaPipe初期化を検証」はカメラなしで公式モデルのロードと推論をテストします。検証範囲と実物の書き出し結果は `VERIFICATION.md` を参照してください。

## 口パク修正（2026-09-06）

銀髪サンプルで音声が出ても口が動かなかった原因は、閉じ口モードに開口差分がなく、口のアニメーション要素が作られていなかったことです。内蔵ImageGenでこのキャラクター用の開口を生成し、口内だけを抽出してVTracerでSVG化しました。生成画像全体への差し替えはしていません。

- 開口素材: `data/donors/silver-mouth-20260906/mouth-open.svg`
- 生成プロンプト: `data/donors/silver-mouth-20260906/PROMPT.txt`
- 元の生成画像: 同フォルダの `generated-donor.png`
- サンプルへの適用: `web/sample-mouth.js`。対象のサンプルID・口パーツ・寸法が一致する場合だけ適用し、既に指定された開口SVGは保持します。
- 音声画面に口パクの準備状態を表示。ブラウザ標準音声でも感度・メーターを反映します。ブラウザ標準は発話中の推定開閉で、波形同期ではありません。
- プロジェクトJSONには音声エンジン・セリフ・感度も保存します。保存済みJSONは `/?project=<書き出しID>` でも復元できるため、内蔵ブラウザの自動ファイル選択を使わず設定を引き継げます。

閉じ目は元のまつ毛画像から色と太さの分布を抽出した塗りSVGを使用します。通常の瞬きと「まばたきを試す」で共通です。既存プロジェクトも元変換が残っていて素材が一致すれば補完され、再保存すると閉じ目差分を持ち運べます。手動で指定済みの閉じ目SVGは保持します。

## 腕と前後の髪を分離する試作

左側の「腕・前髪・後ろ髪も分離（試作）」を有効にして元画像＋PSDを変換します。PSDの後ろ髪・左右の腕や袖の領域を使い、見える色は元画像から切り出します。前髪は元絵の睫毛が残らないよう、See-ThroughのPSD素材の色と透明度を使います。隠れた胴体や後ろ髪の下地にもPSDの補完を使います。元ファイルや以前のプロジェクトは変更しません。

- 「髪の揺らし方」で **PuruPuru参考・波／Anime2.5DRig参考・二重バネ／なし** を切り替えます。波とバネの加算はしません。
- 前髪と後ろ髪は別々の変形と位相で揺れます。前髪0〜6px、後ろ髪0〜18px（1024px幅換算）。「毛先への集中」を大きくすると中間を抑え、毛先で大きく揺れます。
- 腕・袖は肩を支点に0〜2°相当。周囲との境界では動きを補間してつなぎます。0で追加の揺れを停止。腕レイヤーを選ぶと既存の支点X/Yで肩位置を調整できます。パーツの揺れ倍率も反映します。
- 分離素材は顔と胴体の形を保つモードで動きます。左右の目・眉・口、前髪が顔を隠す順序を維持。プレビュー、PNG、動画、単体SVG、保存JSONに対応します。

これは小さな動き用の試作です。AI分離と元画像の境界が一致しない箇所や、素材自体の色差は残ります。自由な腕上げや手動マスク補正ツールはまだ含みません。分離が不要ならチェックを外して従来の変換を使えます。

### 切り口が千切れる問題の修正

別々のメッシュで切り抜きを動かすと、同じ切り口の移動量が食い違って隙間が開いていました。現在はSVGの実際の可視領域から前髪・後ろ髪・腕の重みを作り、境界で滑らかにつないだ一枚のメッシュを使います。前後の髪の強さ・毛先への集中・方式の切り替えは維持しています。境界を保つため、腕を自由に離したり隠れていた面を露出したりする動作には使いません。

以前の分離プロジェクトも読み込み時に境界情報を作成します。作成中は書き出しを待ち、再保存すると境界情報もJSONに含まれます。描画コードは更新を再確認するキャッシュ設定に変更しています。

### 二重バネの振幅と5母音

二重バネは硬い・柔らかいばねを混ぜた後に振幅を正規化し、長い周期でも後ろ髪の動きが弱くなりすぎないようにしました。「速さ」は1ループ内の往復数（1〜4）、「バネの柔らかさ」は硬め0〜柔らかめ1です。振幅は前髪・後ろ髪のスライダーで調整します。毛根固定と境界の補間があるため、全点が設定した最大pxだけ動くわけではありません。

「表情を確認」の「あ・い・う・え・お」で元の口を縦・横に変形した5母音を試せます。「戻す」で手動指定を解除。5母音ONの自動口パクではループ内で順に切り替わり、SVG・動画にも反映します。歯・舌は元素材のままで、母音ごとの描き下ろし差分ではありません。

音声タブの「母音の読み」にひらがな・カタカナを入力すると、読みの母音を時間に割り当てます。Style-Bert-VITS2では生成した音声長、ブラウザ標準では推定発話速度を使用。音声ファイルは読みを入れて「この読みを音声の母音切替に使う」を押します。漢字の読みの自動変換や音声からの母音認識、正確な音素時刻の取得は行いません。5母音OFFでは従来の開閉に戻ります。音声設定の読みとバネの追加設定はプロジェクトJSONにも保存します。

### 絵柄に合わせた口の輪郭

「口の描き方」で「アニメ向けの輪郭・歯・舌」を選ぶと、開口差分のある口を専用のベジェ曲線へ切り替えます。元の口内を縦横に潰す方式とは別で、口角を基準に下へ開き、「い・え」は歯の見える横口、「う・お」は大きさと上下の丸みが異なる口になります。閉じ口には元の絵を使います。FACSの厳密な再現ではなく、この絵柄に合わせた表現です。

「口の高さ（＋で下へ）」は開閉両方の口を動かし、1024px幅換算で−20〜20pxを指定します。今回の銀髪用保存版は+6px。設定はJSON・SVG・PNG・動画で共通です。元絵の開口を直接動かす素材は従来の変形を維持し、開口差分を設定すると新しい描き方を使用できます。


## 現在の口パク方針：開閉に集中

通常UIは一つの開き口と閉じ口を使います。5母音の追加読込・編集・自動切替・読み仮名欄は表示せず、旧プロジェクトも開閉モードで開きます。保存済みの母音SVGと調整値は保持します。

TTS・音声ファイル・マイクは、短い音量低下を90ms保持し、開く反応は速め・閉じる反応は緩やかにしています。閉じ口と開き口を重ねる範囲も縮めました。ブラウザ標準は引き続き推定の開閉です。上記の5母音に関する旧記述は過去の仕様です。

## 髪越しに目元を見せる

目の確認画面の「髪越しに目元を見せる」をONにすると、前髪と重なる睫毛だけを薄く前面に重ねます。「見せる強さ」で0〜100%を調整できます。新規・旧保存は既定OFF、ON時の初期強度は35%です。

同じ睫毛の開閉・閉じ目補正・顔の動きを使い、前髪の透明度と動いた範囲でマスクします。ON中は元絵の固定された睫毛補助レイヤーを描画せず、保存データは保持します。前髪より奥の睫毛や髪以外の場所を一律に前面へ出す機能ではありません。

設定はプロジェクト、PNG・動画・ループSVG・OBSで共通です。接続中のOBSへ編集を反映するときは既存の「反映」操作を使ってください。AI設定APIからは eyeThroughHair（真偽値）、eyeThroughHairStrength（0〜1）で指定できます。

元画像＋PSDの新規読み込みでは、前髪がある場合はPSD由来の素材を採用します。腕・髪の分離がOFFでも同様です。古い保存に焼き込まれた睫毛はこの表示設定だけでは消えないため、素材自体の差し替えが必要です。今回の修正版は別の保存として作成し、元の保存は残しています。

## 目元の下地の自動補修

「元画像＋PSD」の読み込みでは、ベースPSDに分離された `face` / `顔` / `顔の下地` / `顔下地` レイヤーがあれば、アプリが目元の下地を自動補修します。追加の閉じ目・閉じ口PSDは不要です。周囲の肌色に合わせ、補修の端をなじませます。目・口の形や前髪、補修範囲外と透明度は維持します。

補修した場合は読み込み後の状態欄に表示します。顔レイヤーがない場合や、色合わせに使える肌が不足する場合は従来の下地生成を使います。過去の保存は自動で書き換えません。

## AIへの仕上げ依頼・最初からお任せ（P0–P3試作）

AIなしの編集・書き出しはそのまま使えます。開始画面に「自分で作る」「最初からAIに任せる」を追加しました。仕上げだけ頼む場合は「01 形を整える」の「AIに任せる」を使います。「AI補正を確認」から比較・採用・取り消しまで同じ工程で完結します。

依頼文をCodexへ渡すと、外部AIが同じ編集APIで比較画像を確認し、閉じ目・閉じ口を補正できます。「画像生成による素材の補正も使う」を指定した依頼では、利用可能なImageGenで作ったPNGをSVG化して候補へ戻せます。生成と判断は外部AI側が担当し、アプリ内でAIアカウントを設定する必要はありません。

履歴は自動保存し、候補の適用・Undo・別保存・依頼の再開が可能です。最初から任せる場合も、両目と口が開いた元画像と対応するPSDが必要です。導入後はサーバーを再起動し、ブラウザーを更新してください。

## 作業エリアで閉じ形を編集

工程は「目 → 口 → 2 動きをつける」の順です。閉じ形の編集・AI操作は右側にまとめています。パーツの調整は左のレイヤーを選ぶと表示され、終了後は直前の目・口の工程へ戻れます。

閉じ目・閉じ口は左の「手動で編集」と右のAIボタンから操作します。右はその部位が未依頼なら「AIに任せる」、依頼済みなら「AI補正を確認」に切り替わります。希望と画像生成の利用可否を選び、作成した依頼文をCodexへ渡してください。AIの確認が終わると仕上げが自動反映されます。補正前→補正後の顔をひと組だけ表示し、「これでOK」「もう一回頼む」で選べます。「元に戻す」も利用できます。再依頼には前回の対象・希望・画像生成の指定を引き継ぎます。詳しい所見と比較画像はセッションに保存し、結果画面には表示しません。

瞬きでは白目とまつ毛の開口範囲が閉じ、瞳は元の形とハイライトの位置を保ったまま隠れます。瞳自体を縦につぶす処理は使用しません。プレビュー・PNG・動画・OBS・ループSVGに共通です。

目の工程では、気になる目をクリックすると閉じ形との重ね表示になり、その目に編集枠が出ます。枠内で移動、四角で拡大縮小、上の丸で回転できます。自動生成した閉じ形は「カーブ・太さ」で曲がり・線幅を調整できます。長さ・角度は「移動・変形」で調整します。手動編集中はAI操作を隠し、作業エリアの「Undo（取り消す）」「Redo（やり直す）」で編集履歴を操作します。右側にはツール、折りたたみの「数値で微調整」、「完了」「キャンセル」を並べます。「完了」は編集を確定し、「キャンセル」は今回の編集開始時点の形と履歴へ戻します。「開いた形と重ねる」はスライダーのそばに表示します。絵の下のスライダーで開閉を再確認できます。口の工程も口の絵をクリックして編集を始められます。数値欄は右側の微調整として残しています。

## 獣耳・頭飾りの重なり順

元画像＋PSDでは、`headwear`・獣耳・けもみみ・頭飾り・帽子に該当するレイヤーを「PSDの頭飾り」として独立して残します。腕・髪の分離がOFFでも有効です。左の一覧で表示を切り替え、ドラッグや「手前へ／奥へ」で前髪との重なりを変えられます。PSD内で一枚になっている左右の獣耳は、一つのレイヤーとして扱います。

以前の保存に焼き込まれた頭飾りは、自動では分離されません。対応するPSDと埋め込み元画像を持つ分離済みHybrid保存では、`python -m studio.repair_head_accessories <保存JSON> <対応PSD>` で別の修正版を作れます。胴体の絵や配置が編集済みの場合は置換を拒否します。

読み込み前の「SVGの仕上がり（VTracer）」でバランス・高精細・軽量を選べます。白背景の元画像では、PSDで暗い髪として補われた白い隙間も背景除去の対象にします。PSDで白い髪・衣装・顔パーツとして残っている部分、および元から透過のある画像は保護します。色の照合による補修なので、細い明るい縁などが残る場合があります。
