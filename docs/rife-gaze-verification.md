# RIFE使用中の待機視線の復元（2026-09-17）

## 原因と対応

8枚のSVGが瞳を含むため、RIFEの目では元の独立した瞳レイヤーが描かれていなかった。
目が開いている間は元の白目・瞳・まつ毛を描画し、開閉量0〜0.22でRIFEへ滑らかに接続する。
目全体をずらす方式ではなく、通常の白目マスク内で瞳の移動・拡縮を行う。
既存プロジェクトの8枚データを再生成せずに適用できる。

SVGは専用の視線チャンネル、Canvasは目の範囲だけの小さなキャッシュを使う。
Canvasの待機表示でもRIFE推論・SVGの再解析はしない。キャッシュはシーン破棄時に解放する。

## 検証

- JavaScript 242件成功。視線・拡縮・旧コマへの適用・接続境界・局所座標・RIFEへの再帰防止を含む。
- 実キャラクターの既存8枚データでCanvasとSVGの左右視線を比較。
- Canvasの画素差: 開閉0で579,155、0.1で304,746、0.22と1で0。SVGの開閉0では577,654。
- 瞳の倍率0.9と1.1のCanvas画素差は256,129。
- 開閉0.21999と0.22001の境界の画素差は1,269。視線が突然切り替わる大きな差は観測していない。
- 元の20パーツプロジェクトを実装UIへ読み込み、変更した説明と開いた目を確認。
- 画像: `output/verification/rife-idle-gaze-20260917.png`。

RIFEの絵へ接続した後の瞬き途中は、その絵に含まれる瞳を使う。瞬き全体を独立した視線で動かす方式への変更ではない。
