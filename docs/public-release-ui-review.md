## 公開前に優先すること

### 1. 保存・再開で編集結果を見失う導線（優先度：高）

観察：上部の「保存」はサーバーの data/exports にJSONを作り、画面下部に小さいリンクを表示する。「保存済みから再開」の選択一覧は data/projects の変換結果で、編集後に保存したJSONの一覧ではない。別途JSONを選ぶ説明はあるが、保存後に一覧から再開できると考える利用者が誤って元の変換結果を開く可能性がある。保存操作だけではブラウザへのダウンロードも始まらない。未保存変更の表示・離脱時の確認は実装されていない。

提案：「最近編集したプロジェクト」を最初に表示し、編集保存結果から直接再開できるようにする。変換直後の結果は別項目にする。保存後は保存先・再開・JSONをダウンロードの導線をはっきり出す。未保存表示と素材切替・ページ離脱時の保護を加える。

根拠：web/app.js の download / showExport / saveProject / refreshProjects、studio/server.py の save_export / list_projects、web/index.html の source-resume。

### 2. PSDを持っていない人が最初に止まる（優先度：高）

観察：「同じ絵をパーツ分けしたPSD」という説明はあるが、PSDを用意する手順へのリンクやサンプルで試す入口がない。現在の読み込みは元画像と対応PSDの両方が必須。アプリの「絵を分けて」というコピーから、元画像だけでPSD相当の分離もできると期待する可能性がある。

提案：「まずサンプルで試す」と「自分の素材を読み込む」を用意する。サンプルは配布可能な素材を選ぶ。PSD欄のそばに短い準備ガイドを置き、開き目・開き口、同じサイズ・位置、必要なレイヤーを図で説明する。PSDが外部での準備を要することを入口で明記する。

根拠：web/index.html の startScreen / importForm、web/app.js の importHybrid。

### 3. 重ね表示を変換失敗と誤解しやすい（対応済み：2026-09-08）

開き目・開き口から案内ボタンで閉じ形へ進む方式に変更。重ね表示を任意にし、目・口に共通の変形枠とカーブ用ツールを追加。以下は変更前の所見。

観察：目78%・口11%から編集が始まり、開閉両方の形が見える。これは意図した作業状態だが、初回には二重の線や半端な閉じ目として見える。「開閉を重ねて確認」ボタンはあるものの、現在その状態であることは説明されていない。目の案内の「画面の端と中央」は、目のハンドルではなく画面全体の端とも読める。

提案：初期の重ね表示は維持し、「開いた形と閉じた形を重ねて調整中」を短く表示する。「開く／調整用の重ね表示／閉じる」の確認ボタンを置き、ハンドルの意味は対象付近で示す。案内を「目の両端の丸で幅、中央の丸でカーブ」のように具体化する。

根拠：web/work-area.js の初期値、web/edit-guidance.js、実際の目・口の初期画面。

### 4. 用途が違うのに全メニューが一本道に見える（優先度：中）

観察：左の01〜05が編集、モーション、声、配信・AI、書き出しの順。目→口は明確になった一方、ゲーム素材だけ欲しい人には声やAI連携も必要な工程に見えうる。OBSだけ使いたい人にも「AI・OBS接続」という用語が先に出る。

提案：目・口の確認を終えたところで「素材を書き出す／配信で使う」を主な出口として示す。声・AI操作は必要に応じて選ぶ。OBSの画面は「表示を開始→URLをコピー→OBSに貼る」の順にし、外部AIの説明は詳細欄にまとめる。新規起動時に質問を増やす必要はない。

根拠：web/workspace-ui.js の editNext、web/index.html の workflowNav、web/studio-outputs.js の liveOutputs。

### 5. 出力の選択と受け取りが技術用語中心（優先度：中）

観察：書き出し画面で、用途を選ぶ前に「プレビュー・動画・PNGの描画」という描画設定が現れる。ループSVG、WebM、MP4、パーツZIPなどを選び、保存場所は data/exports と説明される。透過の可否や利用先から選びたい人には判断が難しい。

提案：透過の静止画、透過の動く素材、通常の動画、ゲーム用の連番・シートという用途を入口にする。現在の形式ごとの透過対応を明記する。描画方式は詳細設定に移し、完了後に大きなダウンロード操作と保存先を表示する。

根拠：web/index.html の output-image、web/studio-outputs.js の materialOutputs、web/app.js の showExport。

## UI以外の公開準備

- 起動スクリプトはこのPCの I:\python\python.exe を優先し、なければ python に戻る。依存不足時は英語のエラーになる。PythonのないWindowsで最初から起動できる配布・導入手順を決め、クリーン環境で確認する必要がある。
- 本体のルートLICENSEは見当たらない。第三者コードの通知とライセンスファイルはある。本体の公開条件、依存物・同梱素材の一覧を整理する。今回の確認はファイルの有無までで、権利関係の審査はしていない。
- 作業フォルダには data / qa / examples や旧検証ページ、個人PCの絶対パスが含まれる。dataとqaはgitignore対象だが、そのままZIPにすれば含まれる。配布対象を明示したパッケージ作成処理が必要。
- 保存内容の復元、初回起動、実際のOBS・音声入出力を、公開物として組み立てた環境で一巡させる。今回のUIレビューはセキュリティ監査・素材再変換・実機OBS接続試験の代替ではない。
