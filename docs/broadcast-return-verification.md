# 配信モードから制作画面への復帰

## 変更

- 同じウィンドウの配信モードでは、設定パネル上部の「配信を終了して編集に戻る」から、使用中のキャラクターを引き継いで編集画面を開く。
- 「声・背景・位置の準備に戻る」も維持し、構図を復元する。準備画面には「このキャラクターを編集する」を追加した。
- メインメニューへは復帰した画面の左上ロゴから戻る。出力画面にはロゴ・メインメニューリンクを追加しない。
- 既存の `/api/runtime/sessions/{sid}/close` と `/project` を使う。WebSocketの終了通知がHTTP応答より先に届いても、選択した戻り先を維持し、遷移は一度だけ行う。
- APIからの終了は編集画面へ戻る。独立した出力ウィンドウは従来の終了動作を維持する。
- 終了リクエストが失敗した場合は配信画面でエラーを表示し、再試行できる。

## 検証環境

同梱バックエンドを隔離ポート18788で起動し、実装画面をheadless Edgeで確認。ユーザーが使用中の18765には変更を加えない。

実画面の画像: `output/verification/broadcast-return-20260917.png`、`output/verification/broadcast-return-editor-20260917.png`。

## 確認内容

- 保存プロジェクトを「キャラクターを使う」から読み込み、配信開始 → 編集へ復帰。同じプロジェクト名・パーツ数、編集タブを確認。
- 終了APIを一度503にした場合、配信画面で再試行でき、成功後に復帰する。
- 編集後にロゴを押すと保存確認が出る。「編集を続ける」と「変更を破棄して戻る」の両方を確認。
- 準備への復帰時に表示位置・倍率を維持し、そこから再読み込みなしで編集へ入れる。
- APIの `/close` でも同じウィンドウが編集へ戻る。
- ブラウザの未処理例外なし。既存の配信モード単体テスト4件成功。
- 初回の編集画面は読み込み表示を解除してから目元への拡大位置を計算する。
