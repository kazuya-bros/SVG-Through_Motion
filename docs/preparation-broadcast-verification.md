# 準備と配信を同じ再生セッションに統一（2026-09-18）

## 動作

- 「キャラクターを使う」から準備画面を開いた時点で発話・AI演出を受け付ける。AIモデル自体を起動する機能ではない。
- 配信へ進む操作と「準備に戻る」は、同一playerのレイアウト切替だけ。同じWebSocket、描画Canvas、セッションID、演出と入力機器を維持する。
- 配信中は設定、ロゴ、編集への導線を表示しない。マウス移動で1.6秒間表示する「準備に戻る」をホバー・フォーカス中も表示する。Escapeでも準備へ戻る。タッチ環境では戻るボタンを常時表示する。
- 声、背景、入力、表情、AI接続・演出、配信ソフト用URL、デスクトップ設定は準備に集約。「このキャラクターを編集する」は削除。
- プレビュー内の右上に位置・大きさのリセットを配置。ドラッグ移動とホイール拡大縮小に対応。
- 明示的な発話受付・AI演出のオフは切替後も維持。「通常に戻す」は演技を解除し、AI受付は維持する。
- メニューへは準備の左上ロゴから戻る。音声と入力・接続は終了する。
- 音声設定の変更は新しい共通REST/MCP操作 `output.voice` を使用する。発話中・revision競合は409。キーを公開状態やプロジェクトへ含めない。

## 検証

- JavaScript単体テスト254件成功。
- Python runtime / performance / agent control の26件成功。初期受付、音声変更、revision競合、発話中の変更拒否、接続先検証、APIキー非公開を含む。
- 隔離ポート18788とheadless Edgeで実装画面を操作。プロジェクト読込 → 自動待ち受け、ドラッグ・ズーム・リセット、音声変更、マイク・カメラ選択後も受付維持、演出中の往復、ホバー表示、明示的な受付停止、Escape、メニュー復帰を検証。
- 発話は固定APIから準備・配信それぞれに送り、受付からcompletedまで確認。音声合成応答だけを無音WAVに置き換えており、外部TTSエンジンの実機発声や物理カメラ・マイクの収録はこの検証に含まない。
- AI演出の描画開始をAPIで確認し、往復中に同じrequest_id・Canvas要素・WebSocketが維持されることを確認。
- 同梱バックエンドでも上記の導線を再確認済み。「通常に戻す」で単発エフェクトも復元し、AI受付を維持することを確認。ブラウザ未処理例外なし。ユーザー利用中のアプリ・バックエンドには変更を加えない。
