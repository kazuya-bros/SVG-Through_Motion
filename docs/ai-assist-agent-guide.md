# SVG-Through：外部AIの操作ガイド（P0–P3）

本書は「目・口と動きをAIに任せる」専用の補正手順です。素材準備・Depth・発話・表情を含む一般的なAPI / MCP操作は [エージェント制御](agent-control.md) を参照してください。

このガイドは、ユーザーがSVG-Throughの依頼文を渡した外部エージェント向け。アプリはローカルの変換・編集・比較・保存を担当し、画像を見て判断する工程と画像生成はエージェントが担当する。CLI単体は自動視覚補正を行わない。

## 接続と開始

編集画面を開いたままにする。仕上げは「01 形を整える → AIに任せる」。比較・所見・採用・取り消しは同じ工程の「AI補正を確認」で行う。最初からの場合は開始画面で「最初からAIに任せる」を選び、両目・口が開いた元画像と対応するPSDを登録する。任意の一枚絵からのPSD分離は含まない。

接続先は依頼文にあるloopback URLを使う。母艦ではPythonは `I:\python\python.exe`。以下の `SID`、`INPUT_ID` は依頼文の値に置き換える。

```powershell
# 現在の編集からの仕上げ
I:\python\python.exe tools/assist_agent.py --url http://127.0.0.1:8765 begin --session SID
# 登録済みの元画像＋PSDから
I:\python\python.exe tools/assist_agent.py --url http://127.0.0.1:8765 begin --input INPUT_ID
```

画像を読む能力とローカル編集APIの利用可否を確認してから実行する。実際に画像生成ツールを利用できる場合だけ `--images` を追加する。モデル名や契約名だけで機能の有無を決めない。ユーザー側の「画像生成による素材の補正も使う」が無効なら、生成操作は拒否される。

`begin` は依頼の受理と最初の17枚の比較PNGのZIP出力まで行う。`--input` は変換開始・監視・読込も行う。以後の再開には出力された `session_id` を使う。変換開始APIは同じ入力IDの二重変換を防ぐ。変換途中でサーバーが停止した場合は `interrupted` を報告するので素材を再登録する。

## 比較して補正する

### 「最初からAIに任せる」の担当範囲

`workflow.mode=from_inputs` は、元画像＋PSDの変換、目・口の補正、動きの調整までを担当する。TTSエンジン・声・音声設定を変更しない。発話、マイク・カメラ、出力ウィンドウの起動、動画や素材の書き出しは行わない。比較画像と補正候補の保存は確認工程として行える。

目・口を整えたら、`inspect` の `motion.values` と `motion.fields` を確認し、`motion` 操作の `settings` に希望に合う値を渡す。通常は控えめな待機を基準とし、体の揺れ・呼吸・瞬き・頭の傾き・髪の追従を元絵に合わせる。腕など存在しない部位を無理に動かさない。元の動きが適切なら、その値を明示して確認する。動きの調整は6回まで。`/api/control/commands` の通常の `settings` 操作でライブ編集を変更せず、必ず補正候補への `motion` 操作を使う。

```json
{"operation":"motion","operation_id":"motion-01","session_id":"SID","revision":2,"settings":{"duration":4,"sway":0.3,"breathe":1,"blink":true,"talking":false,"headTilt":1.2,"headNod":0.5}}
```

`motion` でrevisionが更新される。再度 `review` を作り、開閉に加えて `review-09.png`～`16.png` の動きを確認する。比較の左は開始時、右は候補自身の動き。同じループ進行率で比較し、ループ長は各設定を使用する。`finish` には確認したモーション画像もevidenceに含める。動きの設定・最新比較なしで完了にはできない。

このルートは自動反映が既定。成功すると「動きをつける」画面で再生し、「これでOK」「もう一回頼む」「AIに頼む前に戻す」を表示する。目・口と動きは一緒に取り消せる。ユーザーには短く完了を伝え、TTSや出力の設定はユーザーに引き継ぐ。後続の手動変更と競合したら現在の編集を優先し、候補を別保存する。

1. `inspect` で希望、生成利用可否、部位ID、現在値、編集可能な項目と範囲を取得する。
2. `review` が返すローカル `path` のZIPを作業領域へ展開し、実際のPNGを画像確認ツールで読む。全体と顔の拡大を確認する。左は開始時、右は現在の候補。
3. 開いた元形との位置関係、閉じた線の幅・傾き、閉眼途中、口の開閉途中、待機モーションを見て、必要な部位だけ絶対値で編集する。
4. 再び `review` を実行し、最新revisionのPNGを読む。数値が変わっただけで「改善」と判定しない。
5. 最良の候補を選び、`finish` へ変更内容・画像所見・未解決点を記録する。改善しない場合は `restore` で以前のrevisionへ戻すか、変更なしで未解決点を提示する。

比較ページは `review-00`～`03` が閉眼率0/50/80/100%、`04`～`07` が口開度0/25/50/100%、`08` が両方閉、`09`～`16` が待機モーション8時点。ファイル名の末尾は `.png`。明暗の背景はページごとに交互になる。`review.json` に描画条件を記録する。

操作JSONはUTF-8ファイルに保存して `call @ファイル` で渡すと、PowerShellの引用符や日本語の扱いを避けられる。

```json
{
  "operation": "edit",
  "operation_id": "eye-position-01",
  "session_id": "SID",
  "revision": 0,
  "part_id": "p003",
  "values": {"y": 0, "width": 1}
}
```

```powershell
I:\python\python.exe tools/assist_agent.py --url http://127.0.0.1:8765 call @edit.json
```

`x/y/curve` は原画基準px、`angle` は度、`width/height/thickness` は倍率。曲線・線幅の編集は形状を解析できる自動作成線だけ。PNGから取り込んだ線は位置・拡縮・回転を使う。`inspect` に出ない項目は送らない。

`operation_id` は1操作につき固定する。同じ内容・IDの再送は保存済み結果を返す。通信が途切れた場合は、新しいIDで同じ変更を繰り返さず、依頼を再開して同じIDで照合する。古いrevisionは拒否される。CLIは `call` にIDがない場合は補うが、再送する操作はファイルへ明示しておく。

数値編集は部位ごとに3回、生成依頼はセッション全体で2件、候補履歴60回、操作結果200件が上限。`restore` や再開で試行回数は戻らない。生成回数の制限はアプリが発行する素材依頼数であり、外部ツールの全呼び出しを監視する機能ではない。

## ImageGenの往復

1. `prepare_asset` にsession_id、revision、part_id、operation_idを渡す。参照PNG、対象座標・寸法、素材リクエストID、元の閉じ形のSHA-256が返る。
2. 参照画像を実際に開く。ユーザーの希望に沿い、対象の閉じ目または閉じ口だけのPNG差分を生成する。利用環境の画像生成スキルに従い、生成指示と出力を作業記録に残す。アプリのHTTP APIから内蔵ImageGenを直接呼ぶ仕組みはない。
3. 生成PNGを目で確認し、線の周囲の余白も含めた切り抜き範囲を決める。PNGが元絵と同じ寸法でも、位置が一致するとは扱わない。
4. `import-asset` でアップロードする。`crop` は生成PNGのpx、左・上・右・下（右下は範囲外）。切り抜き全体が対象パーツの寸法へリサイズされる。縦横比を保ちたい場合はcropの比率を対象に合わせる。

```powershell
I:\python\python.exe tools/assist_agent.py --url http://127.0.0.1:8765 import-asset REQUEST_ID donor.png --crop 0,0,1100,640 --extraction alpha --placement-confirmed
```

透過PNGは `alpha` を使う。不透明画像を自動で透明と解釈しない。単色の閉じ線を明るい背景から抽出する場合のみ、画像確認後に `dark_ink` を明示できる。これは暗い画素の抽出であり、汎用の背景除去や顔下地補修ではない。抽出後のPNGプレビューも確認する。

5. 戻った `asset_id` を `attach_asset` で同じrevisionへ差し込む。閉じ形だけを交換し、開き形は維持する。古いrevision・別の依頼・ハッシュ不一致・終了済みの候補は拒否される。
6. `review` を作り直し、閉じ形・開閉途中・開き切った形・動きの中で確認する。生成PNGが良くても、SVG化や縮小で劣化したら採用しない。

生成待ちは `waiting_asset` として保存されるため、長時間の実行中コマンドは残らない。「候補を終了」で取り込み先を閉じられる。外部画像生成自体の停止や料金・消費量の制御はアプリの担当範囲外。

## 所見・採用・保存

通常UIからの依頼は `workflow.auto_apply=true`。最新画像を確認して `finish` を送ると、仕上げを元の編集へ自動反映する。戻り値が `applied=true` なら `apply` を重ねて送らない。ユーザーには簡潔な完了結果だけ伝え、17枚の比較画像や確認作業を要求しない。比較画像・詳しい所見は「詳細」に保存される。「元に戻す」「もう一回頼む」が通常の操作となる。

自動反映時に後続の手動変更が見つかると `workflow.apply_error` に理由を記録して候補を保持する。現在の編集を上書きせず、必要に応じて別保存する。旧依頼や手動候補で `auto_apply` がない場合は従来の明示的な `apply` を使う。

```json
{
  "operation": "finish",
  "operation_id": "finish-01",
  "session_id": "SID",
  "revision": 2,
  "assessment": {
    "status": "limitations",
    "notes": "閉じ目の高さと幅を整えた。完全閉眼は改善。80%付近の重なりは残るため比較画像を確認してほしい。",
    "evidence": ["review-02.png", "review-03.png", "review-08.png"]
  }
}
```

実際に確認した最新PNGの名前をevidenceへ列挙する。`pass` は確認した範囲の判定、`limitations` は未解決点や評価範囲の制限あり。アプリは所見の形式を検証するが、エージェントが画像を見たこと自体は検証できない。

ユーザーには候補の比較と所見を提示する。元編集への反映は「候補を適用」、プロジェクト出力は「候補を別保存」。途中の調整ごとの承認は不要。最終採用まで委ねられた依頼なら `apply` も実行できる。AI受理済みの候補は最新比較とfinishなしでは適用できない。

開始後に元の編集が変わっていたら、適用は拒否される。現在の編集を上書きせず候補を別保存する。適用後のUndoも後続編集があれば拒否する。候補は履歴復元も可能だが、ユーザーの通常編集を自動停止する機能は試作にはない。

保存した依頼はUIの「保存した依頼を探す → 再開」、または `begin --session SID` で再開できる。元プロジェクトも同じ状態で開く必要がある。変換済み素材は通常の `load` コマンド（source=project）、保存済み出力はsource=savedを使う。元と一致しない状態でも候補の確認と別保存はできる。

プロジェクトを別保存すると、PNG由来の閉じ形もSVGとして内包される。受け取る側にAI接続や補正履歴は不要。補正セッションは `data/assist/sessions/` の追記式gzipチェックポイント、依頼は `inputs/` と `requests/`、生成素材は `assets/` に保持する。PNG・比較ZIP・プロジェクト出力は新規IDへ保存し、自動削除しない。

## 実装範囲

P0の共通コマンドにP1の外部AIレビュー、P2のPNG差分取り込み、P3の登録素材からの開始を接続した試作。CLI/API契約は `studio/control.py` と `/api/docs` が実装上の基準。

一般操作の専用MCPと、素材準備画面・API経由のSee-Through分割は追加済みです。アプリ内の常駐LLM、生成画像の自動ランドマーク合わせ、任意SVGパス編集、顔下地の生成補修、実ユーザーの絵柄に対する品質評価は今後の範囲。補正ワークフローの過去の記録は [実装・検証記録](ai-assist-p1-p3.md) を参照。
