# リアルタイム演出とキャラクター切り替え

## 演出編集

- 要素の値は変更すると自動でプレビューへ反映。連続操作を120ms単位でまとめ、再生位置を引き継ぐ。追加・削除／プレビューボタンは最初から再生。保存は従来の「演出を保存」。
- 動く要素には強さと速さ（0.25〜4倍）がある。速さは移動、粒、走査線、ノイズの周期に反映する。
- 「輪郭ノイズ」はときどき輪郭の外側がずれる効果。「通信っぽいエフェクト」と組み合わせられる。
- 「ノイズブロックから現れる」は四角いノイズが集まって現れる登場効果。粒・線・消滅と同時には登録しない。
- 縁取りは境界線／2重／3重を選択。使う色数は縁の数まで選択できる。既存設定は白→指定色→白を維持。
- 感情画像の新規追加は非表示。既存データとAPI互換は保持。

## 配信準備

「キャラクターの切り替え」で保存済みキャラまたはプロジェクトJSONを追加し、キャラと演出を選択する。追加は8体・合計250MBまで。同じプロジェクトIDの別ポーズも素材スナップショットで区別する。

ホットキー設定は行ごとに「キャラクター」「表情・演出」「グローバルキー」を選ぶ。特定キャラを指定する行は保存済み演出を使用。キャラを「表示中のキャラクター」にすると従来の表情キーも使える。

配信画面と配信ソフトのURLは維持される。読み込み中は現在の絵を表示し、描画準備後に切り替える。頻繁な切り替え向けに描画済みキャラを最大2体保持。それ以上は切り替え時に再準備する。追加一覧は出力セッション単位なので、新しい出力を開いた場合はキャラを再追加する。

## API / MCP

- GET `/api/runtime/sessions/{sid}/characters`：登録一覧、表示中ID、各キャラの演出。
- POST 同URL：`{project, label?}`。返る `added_id` を切り替えに使用。同一スナップショットの再登録は同じID。ラベルはファイル名などの表示名。
- GET `/api/runtime/sessions/{sid}/characters/{identity}/project`：登録した素材。
- POST `/api/runtime/sessions/{sid}/characters/switch`：`{request_id,character_id,preset_id}`。202受付。最後の指定を優先。
- GET `/api/runtime/sessions/{sid}/characters/result/{request_id}`：loading / completed / interrupted / failed。演出の描画結果は `effect_result_url`。
- MCP：`output.characters/add_character/character_project/switch_character/character_result`。
- 演出プレビューの `update_preview_id` は直前のプレビューID。再生位置を維持した値の更新に使用。
- 演出 `components[].speed` は0.25〜4。新要素は `glitch`、`blocks`。縁取りは `appearance.outline_layers`、`outline_color_count`、`outline_color`、`outline_color2`、`outline_color3`。

グローバルキーはデスクトップアプリで登録する。ブラウザ単体では配信準備のボタンか同じAPIで切り替えられる。

## 検証

- 実素材によるUIテスト：値の自動反映、連続入力の集約、再生位置維持、速さ、縁取りの種類・色数、感情画像の非表示。
- 実素材による配信テスト：キャラ追加、専用演出の選択、同じURLでのプレイヤー／配信ソフト用画面の切り替え、API再送、別キャラの演出の拒否。
- 描画テスト：ブロック登場の開始／中間／完了、倍速、周期的な輪郭ノイズ、動きを減らす設定、縁取りの1〜3重。
- ネイティブ設定UIの橋渡しテストとRust検証：キャラ＋演出＋キーの保存引数、無効なキャラIDの拒否、旧設定互換。
- Python：切り替え競合、失敗時の元キャラ保持、同一IDの別ポーズ追加、ネイティブAPI、演出・MCP。
