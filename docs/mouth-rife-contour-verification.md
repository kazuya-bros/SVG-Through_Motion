# RIFE中間の口を活かす補正の検証（2026-09-17）

## 変更

- 生成されたRGBAの各列で、透過率を面積として縦方向へ詰める。薄い大きな開口を小さな濃い開口へ補正し、RIFEの曲がりと内部色を残す。意図した素材の不透明度は維持する。
- 補正画像の変化量で8枚の時刻を選び、SVG化する。元の開口SVGへの置き換えは行わない。
- 各コマの上端・下端を17点で測定し、隣のコマと同じ中間輪郭へ変形してから混ぜる。SVG作業画面とCanvasは共通の対応メッシュを使用。SVGの区切りの透過線を加算合成で防止する。
- 旧stableは「元SVGを変形（比較用）」として残し、生成後の標準はsvg-frames。既存の8枚は口だけ再生成が必要。目の生成・視線処理は変更しない。

## 検証

既存の20パーツ・8枚RIFEを持つ検証プロジェクトを使用。ユーザーが開いている22パーツの未保存プロジェクトや18765ポートのプロセスは変更しない。独立した検証用データと18788ポート、headless Edgeで実装画面を確認。

- JavaScript全体250件成功。その後追加したメタデータ検証を含め、対象14件を再実行して成功。
- Python RIFE sequence / morph / control / agent control / MCPの26件成功。
- 配布用の凍結バックエンドから、編集APIのrife generateで口を再生成し、completedとappliedを確認。
- inspectで8枚・素材一致・有効状態・svg-frames・alpha-compact-v1を確認。保存したプロジェクトを別のブラウザセッションで再読み込みして維持を確認。
- 不正な輪郭座標、目への口補正メタデータ、8枚のない口補正メタデータを拒否。
- 0〜100%を101段階で描画。途中で静止する区間なし。最終1%の差分509019は全体最大1338130を超えない。この指標は滑らかさの主観評価の代わりではない。
- 8枚のキー位置と、同じラスター化・表示サイズで直接描いた各SVGを比較。premultiplied RGB平均誤差は0枚目0.0000242、残り7枚0（0〜255）。
- 11%の通常SVG変形との画素差2244935を確認。RIFEの中間の絵が使われていることを、チャンネル構成と比較画像でも確認。
- 口だけを1280pxの透明キャンバスへ120回描画した平均は約0.50ms。キャラクター全体の性能を表す値ではない。
- 実装画面で11%の薄い大きな輪郭と、メッシュの区切り線が改善したことを確認。未処理のブラウザ例外なし。
