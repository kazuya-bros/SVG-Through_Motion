# 目・口の補正API：P0の最初の実装

2026-09-09のP0実装時点の記録。候補作成・数値補正・比較・適用・取り消し・別保存を実装した。その後、外部AIのレビュー・生成PNG取り込み・最初からお任せ・永続化を追加した。現在の状態は [P1–P3実装記録](ai-assist-p1-p3.md) を参照。

## 画面から使う

サーバーを再起動し、編集画面を更新する。素材を読み込み、「配信・AI連携」→「目・口の補正候補（試作）」を開く。

1. 「現在の状態から候補を作る」。元の編集とは別の候補ができる。
2. パーツ・調整項目・変更後の絶対値を選び「候補を調整」。
3. 「補正前後を比較」。左が開始時、右が候補。全体と顔の拡大を確認する。
4. 「候補を適用」で現在の編集へ反映する。「適用前へ戻す」で補正全体を取り消す。
5. 「候補を別保存」で、採用前でも通常のプロジェクトJSONとして新規保存できる。

このパネルはAIへの接続なしで使える。画像から取り込んだ閉じ形は位置・拡縮・傾き、対応する生成線はカーブ・線幅も調整できる。元の開き目・開き口・他の素材は書き換えない。既存の直接編集も継続して使える。

## AI・スクリプトから使う

素材を開いて「AI・OBS接続を開始」。既存のRESTブリッジを再利用する。

```powershell
python tools/studio_control.py command @command.json
```

`command.json`の例：

```json
{"action":"assist","assist":{"operation":"inspect"}}
```

`inspect`は現在のプロジェクト、部位ID、現在値、許容範囲・単位と、候補があれば候補の状態を返す。SVG全文は返さない。

| operation | 必要な引数 |
|---|---|
| inspect | なし |
| start | operation_id |
| edit | operation_id, session_id, revision, part_id, values |
| restore | operation_id, session_id, revision, target_revision |
| review | session_id, revision |
| apply | operation_id, session_id, revision |
| undo | operation_id, session_id |
| cancel | operation_id, session_id |
| save | session_id, revision |

```json
{"action":"assist","assist":{"operation":"start","operation_id":"start-001"}}
```

返された`session_id`と`revision`を使用する。下記のIDは説明用で、実際の戻り値に置き換える。

```json
{"action":"assist","assist":{"operation":"edit","operation_id":"edit-001","session_id":"00000000-0000-0000-0000-000000000000","revision":0,"part_id":"p001","values":{"y":3,"angle":-2}}}
```

`values`は差分量ではなく絶対値。pxは画像キャンバスの単位で、+Xが右、+Yが下。部位ごとの回転・拡縮・開閉による見た目の変化は比較画像で確認する。範囲外や未対応の値は拒否し、黙って丸めない。

成功した同じ操作ID・同じ内容の再送は、その結果を返して重複適用しない。同じIDに異なる内容は拒否する。操作の受付と完了は従来どおり別なので、クライアントの完了待ちか結果GETを使う。

比較出力は新規フォルダの`correction-review.zip`。PNG 17枚＋描画条件の`review.json`を含む。目の閉眼率0/50/80/100%、口開度0/25/50/100%、両方閉じ、動き8時点を使う。明色と暗色背景はページごとに交互。マイク・カメラ・現在の再生時刻は使わない。

`apply`は最新revisionで比較画像が作られている場合だけ可能。ただし画像の生成自体は視覚品質の合格を意味しない。AIは画像を実際に見てから適用を判断する。

## 競合と保存

- 候補に独立したrevisionを持ち、古いrevisionからの変更を拒否する。
- 元の編集が開始時と変わっていたら適用を拒否する。別保存か新しい候補でやり直す。
- 適用後に手動編集した場合も、補正Undoで上書きしない。
- 候補は1件、変更履歴60回、成功操作の記録200件まで。終了した候補から新しい候補を作れる。
- 採用・Undoでは補正が所有する目・口の数値だけを書き戻し、素材・レイヤーID・音声設定を保つ。
- 候補と再送防止記録は編集中のタブのメモリ内。再読み込み・タブ終了後の自動復旧は未実装。サーバー再起動時も、再接続して`inspect`するまで結果を推測しない。
- 別保存したJSONは元プロジェクトと同じ形式で、画像を内包して通常の保存読込経路で開ける。
- OBSへの更新は既存の「編集内容をOBSへ反映」を使用する。

## 設計案との差分と次の作業

今回のAPIは`/api/control/commands`の`action=assist`に追加した。独立した`/api/assist`経路、永続的なセッション履歴、全手動編集を通したrevision管理は未実装。既存の手動編集との衝突は、開始時と現在の編集内容の比較で検出する。

既存の形状正規化・描画処理を共有し、追加パネルとAIは同じ`applyShapeEdit`を使用する。従来のドラッグ編集全体を新コマンドへ移行する作業は残る。比較描画中の即時キャンセルも未実装。

次はセッションの保存・再開と編集履歴の統合を進め、P1のAIによる視覚レビュー工程へ接続する。その後にImageGen素材の取り込み、最初からお任せを実装する。
