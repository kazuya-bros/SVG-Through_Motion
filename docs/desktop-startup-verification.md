# 開始画面の直接起動 — 2026-09-15

通常起動は保存先の手入力を要求せず、既存の制作メインメニューを開く。
設定ウィンドウは最初は非表示。起動エラー時、またはアプリメニューから開く。
既存の保存先は維持し、未設定の場合のみEXEの隣のdataを選択して保存する。
ネイティブ設定コマンドは引き続きローカルの設定ウィンドウだけに制限する。

## 確認済み

- Rust 3件成功。初回保存先、EXEの場所変更時の引き継ぎ、相対パス・ポート0拒否、既存のキー検証。
- Pythonのdesktop APIテスト3件成功。認証・外部Origin拒否とセッション操作。
- desktop.js構文チェック、Tauri releaseビルド成功。
- 実Windowsアプリを検証専用設定・ポート18769で起動。空の保存先から自動でdataが作成・保存され、制作メインメニューだけが表示された。
- ネイティブの「アプリ → アプリ設定・ホットキー」で設定を開き、保存先の変更を保存。設定ファイルへの反映を確認。
- 左上ロゴで設定を閉じて制作へ復帰。制作ウィンドウの閉じる操作で終了確認が表示され、終了後に同梱サーバーの正常終了を確認。
- 再起動時もメインメニューだけが表示され、変更済み保存先のディレクトリが作成された。
- 最終ZIPはCRCチェック成功、内包EXEと検証したrelease EXEのバイト一致を確認。
