# RIFEの中間の口を活かす補正（2026-09-17）

口の確認画面は、生成したSVGから口領域の描画キャッシュを作り、開閉・拡大・移動で再利用する。再生中の大量のSVG要素の組み直しは行わない。保存・SVG書き出しにはベクターの素材を保持し、直接編集時はSVGを操作する。詳細は [rife-preview-performance-verification.md](rife-preview-performance-verification.md) を参照。

口の標準再生は「RIFEの8枚SVGを補間」。生成した中間コマの形と色を使う。薄い部分を単に濃くすると大きな残像が残るため、各列の透過率を面積として縦方向へ詰め、RIFEの重心・色・不透明度の総量を保った小さな開口へ補正してからSVG化する。元の開き口SVGを縮める方法ではない。意図したレイヤーの不透明度も維持する。

隣り合うコマの輪郭を17点ずつ測定し、同じ中間輪郭へ局所的に変形してから色を混ぜる。全体の上下範囲だけで閉じ口を引き伸ばす処理は、補正後の口では使わない。8枚のキー位置は各コマの元の形に一致する。閉じきり・開ききりには元の端点SVGを保持する。再生時のRIFE推論は不要。

**古い8枚は「8枚のSVGを作る」で口だけ再生成が必要。** 保存したプロジェクトには補正済みSVGと輪郭情報が含まれる。UIは旧データの場合に再生成を案内する。生成結果の確認ではSVG・SVG化前の補正画像・補正前のRIFE画像を比較できる。瞬きの方式は変更しない。

前回の「輪郭を保って補間」は、実際には元SVGを変形する方式だったため、「元SVGを変形（比較用）」へ改称。明示選択したstableは互換性のため維持するが、8枚生成後はsvg-framesを選択する。旧svg-frames-rawも8枚再生として扱う。gridは従来のグリッド変形。

補正は小さな口パーツの縦方向の透過のにじみを対象とする。RIFEが描いた歯や口角そのものの誤りを自動修復するものではない。生成した8枚を確認して使用する。

# 目・口のRIFE中間形状（試用）

## 使い方

1. 「形を整える」の「目」または「口」を開く。
2. 開閉差分を確認し、「8枚のSVGを作る」を押す。
3. 開閉スライダーを往復して確認する。「生成したコマを確認」でSVGとSVG化前のRIFE画像を比較できる。「中間形状を使う」でON/OFFを比較する。
4. プロジェクトを保存する。8枚のSVGと再生方式・ON/OFFも含まれるため、元PSDやRIFEモデルのない環境でも再生できる。

再生方式の「従来の変形で動かす」で、以前の軽量グリッド方式に戻せる。「変形の強さ」の設定欄は従来のグリッド方式専用。明示的にgridを選択したプロジェクトは、その再生方式を維持する。

目は白目・瞳・まつ毛と閉じ目差分、口は「元絵は開口」の素材と閉じ口差分が対象。今回は閉口素材＋別の開口差分、合成口、母音ごとの補間には非対応。左右の目は別々に生成する。強さは目・口共通。

生成中は進捗と中止を表示する。生成中に素材が変わった場合は結果を適用しない。生成後に元SVG、閉じ差分、位置・サイズ・役割を変更すると、その対象の補間は無効になり、再生成を案内する。既存のプロジェクトは自動変更しない。

目の8枚再生は上下位置・高さを合わせた連続ブレンドを維持する。口の補正と輪郭対応には8枚の再生成が必要。

## 仕組みと限界

- 実際の開閉SVGを最大256pxの局所画像に描画してRIFEへ渡す。開閉を含む8枚、つまり中間6枚を使う。
- 中間画像をVTracerで直接SVG化する。開ききり・閉じきりには元のSVGを保持する。RIFEの線や塗りを残しやすいが、ラスタ推論と再ベクター化のため細部は元絵と完全には一致しない。
- 透過はRIFEの最終フローと混合マスクをアルファにも適用する。色を透過色として抜く方式ではなく、緑色の絵も保持する。
- 5点の開き量による粗い時間推定に加え、33点の等間隔・推定点・端点近傍の画像を測定する。透過込みの色の変化量を累積し、見た目の変化を7区間へ分配する。最後の元SVGにつながる正確な端点も測定に含む。
- 目と未補正の旧データは、隣接する2枚の上下位置と高さを揃えながら連続ブレンドする。補正済みの口は局所的な輪郭対応を使う。各キー位置と0/1はそのコマそのもの。アルファを含めて加算合成し、重なる部分が途中で薄くなるのを防ぐ。
- SVG表示・SVG書き出しはベクターの変形と不透明度を補間する。分離グループ内の `mix-blend-mode:plus-lighter` を使用し、Edgeで確認している。別のSVGビューアでは対応状況によって見え方が変わる。Canvas表示・動画では局所サイズの8枚と混合用バッファをキャッシュする。再生中にRIFEやSVG変換は実行しない。
- 高さ合わせは局所的な縦方向の補正で、線や瞳の位置をすべて対応付ける処理ではない。素材によって薄い二重線やぼけが残ることがある。
- 待機中は元の白目・独立した瞳・まつ毛を使い、視線移動と瞳の拡縮を維持する。開閉量0〜0.22で通常の目からRIFEの目へ滑らかに接続し、それ以降は瞳を含むRIFEの絵を使う。完全に閉じた目には瞳を描かない。既存の8枚データにも再生成なしで適用される。
- この復元は待機中と瞬き開始時のもの。瞬き全体を通して瞳を独立操作する場合は「従来の変形」を使用する。顔全体の動きには両方式とも追従する。
- 保存容量と初回読み込み時のメモリは増える。検証キャラクターでは左右の目と口で約14.2MBのデータが追加された。確認用PNGはプロジェクトに保存しない。
- 従来方式は5列×2行・5キーのグリッドに近似し、元ベクターと独立した瞳を使う。8枚生成時も比較用にグリッドを保持する。

## API / MCP

編集画面をAI・OBS接続したうえで、`editor.command`（`POST /api/control/commands`）に送る。

```json
{"action":"rife","rife":{"operation":"generate","target":"all","mode":"svg-frames"}}
```

`target` は `eyes` / `mouth` / `all`。`mode` は `svg-frames`（編集コマンドの既定値）/ `grid`。`operation: inspect` で生成済み・素材一致・有効状態・SVG枚数・方式・補正識別子（correction）を取得。返却されたコマンドIDを `editor.result` で確認し、`completed` と `applied` を確認して完了とする。UIと同じ生成・競合照合・適用処理を実行する。

```json
{"action":"settings","settings":{"rifeEyes":true,"rifeMouth":true,"rifeEyesMode":"svg-frames","rifeMouthMode":"svg-frames"}}
```

画面を経由しない生成は `rife.status` / `rife.generate` / `rife.job` / `rife.cancel`。`rife.generate` は `request_id`, `kind`（eye/mouth）, `anchor`（画像高に対する支点Y）, `start`, `end`（同サイズの16〜384px PNG data URL）, `mode` を取る。直接生成APIの `mode` 既定値は後方互換のため `grid`。8枚生成には明示的に `svg-frames` を指定する。

結果に5キーの正規化Y座標、確認用PNG、早閉じ補正の有無を返す。8枚モードでは `svg_frames`（at/source_time/svgText/paths/bounds（正規化した上下端））と `svg_size` も返す。口には `mouth_correction: alpha-compact-v1` と各コマの `profile`（17点の正規化上端・下端）、`raw_references`（補正前PNG）を追加する。`references` は補正後・SVG化前の画像。保存時は特徴の `mouthCorrection` と各SVGコマの `profile` として保持する。直接APIの端点はPNGをSVG化したもの。編集UI/APIでは元の端点SVGに置き換えて保存する。ジョブIDの再取得では推論し直さない。同一request_id・同一入力は直近16件以内で同じジョブを返し、異なる入力は409。別の生成中も409。中止時は現在の推論・トレースが終わった後に解放する。

`rife.status` の `active_jobs` から進捗中のジョブを取得できる。編集コマンドが実行中の場合も、`rife.cancel` で中止できる。参照・ジョブ履歴は再起動で消える。保存済みプロジェクトの補間は残る。

## 開発・配布

`requirements.txt` のONNX Runtimeを導入し、監査済みPractical-RIFE v4.9.2モデルを `SVG_THROUGH_RIFE_MODEL` で指定するか `.desktop-build/models/rife.onnx` に配置する。ハッシュを検証してから読み込む。デスクトップビルドはモデルとCPUランタイムを同梱する。生成にはネットワーク・GPU不要。
