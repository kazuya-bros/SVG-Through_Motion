# 高品質SVG変換

PNG／PSDの読み込み、元絵＋PSDの読み込み、素材編集後のSVG化は、既定で `quality` を使います。変換は端末内のVTracerで動き、Codexや画像生成サービスへの接続は不要です。

## 共通処理

- RGBを最大4倍に拡大してから曲線をトレース。1280pxの素材は通常4倍です。
- トレース内部に2pxの余白を追加し、透明部分のRGBを近くの有効な色で補完してから拡大します。パーツの元の位置・寸法は変えません。
- 透明度は7段階の二値輪郭を重ねた独立のマスクにします。白い矩形から黒い背景を引く旧方式を使わず、SVG単体で透明な輪郭を描けます。
- 瞳の役割があるパーツでは、元画像から色相と縦方向の色変化を推定します。十分な色の一貫性と近似精度がある場合だけSVGグラデーションを適用し、暗い線・瞳孔・白いハイライトは残します。複雑な模様や複数色の瞳は通常トレースに戻します。
- PSD／元絵切り抜きの代替素材、追加の閉じ目・閉じ口PSDにも同じ変換を使います。
- 高品質で作成した新規プロジェクトはSVG描画を既定にします。元PNGもプロジェクトに残します。既存プロジェクトは自動で再変換しません。

SVGにはパスとグラデーションを保存し、PNGを埋め込んでSVG化したように見せる処理はしていません。

## 負荷と制限

内部画像は32メガピクセルを上限に、拡大率を4→3→2→1倍へ下げます。一辺8192pxを超える拡大もしません（元画像の縮小はしません）。入力は16メガピクセル・一辺16384px以下です。

VTracerは専用の子プロセスで実行します。変換中もUIとAPIの進捗取得に応答し、1パーツ5分で失敗を通知します。デスクトップアプリ終了時には子プロセスも停止します。変換は従来の標準より時間がかかり、複雑な絵はSVGサイズも大きくなります。`balanced` / `detail` / `light` は互換性のため残しています。

試作で行った、特定の顔の座標を指定して頬の赤みを描き直す処理は汎用化していません。頬や服の柔らかな陰影にはトレースによる段階化が残ることがあります。PSDの欠損や元からある線を自動で描き直す機能でもありません。

## API / MCP

- `POST /api/import`：PNGまたはPSD。multipartの `preset=quality`（省略時も同じ）。
- `POST /api/import/hybrid`：元絵＋PSD。multipartの `preset=quality`。
- `POST /api/materials/{mid}/convert?preset=quality`：素材編集後。query省略時も同じ。
- 各操作が返す `jobId` を `GET /api/jobs/{id}` で確認し、完了後は `GET /api/projects/{id}` でSVG・元画像・位置・役割を取得します。失敗は `state=error` と `message`、同時変換は409です。
- MCPは既存の `projects.import` / `projects.import_hybrid` / `materials.convert` / `projects.job` / `projects.get` と共通です。
- 変換結果の `conversion.traceProfile` は `supersampled-contours-v1`。個別SVGの `data-trace-scale` に実際の拡大率、`data-iris-gradients` に瞳の補間を適用したパス数を記録します。

RIFEの連番SVG生成は独立した処理で、今回その既定品質は変更していません。

配信起動・AI/OBS連携の受け取り上限は、元絵切り抜きなどの代替SVGを含む高品質プロジェクトを扱えるよう、プロジェクト読み込みと同じ100MBに統一しています。
