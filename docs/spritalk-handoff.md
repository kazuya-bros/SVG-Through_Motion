# SpriTalk側へ渡す依頼文

以下をSpriTalk側の開発タスクへそのまま渡してください。これは実装依頼用の文面であり、本ファイルを作成した時点で送信・改修を実施したものではありません。

---

SVG-Throughで作成・調整したキャラクターを、**動きと画質を維持してSpriTalkで使えるように改修**したいです。

仕様書: `E:\SVG化\docs\spritalk-integration-spec.md`

関連ソース:

- SVG-Through: `E:\SVG化`
- SpriTalk: `E:\develop\spritalk`

別PCへ渡す場合は仕様書も添付してください。上記パスは現在のPC上の場所です。

方針は、SVG-Throughの再生パッケージを基準に、SpriTalk側に専用の読み込み・表示方式を追加することです。既存のPachiPaku設定への近似変換ではなく、**描画と動きの処理を共通モジュールにして両アプリで使用**してください。

最優先条件:

1. 前髪・後ろ髪、耳ピコ、胸揺れ、腕、瞳、顔の向き、Faceだけの顎変形を、現在の強さ・周期・位相・支点・局所変形のまま再現する。
2. 元絵/編集済み素材の選択、線・色・透過・差分・マスク・重ね順・解像度を保持する。再トレース、減色、低解像度化、単純な回転への置換で軽量化しない。
3. SpriTalkは実際の音声再生位置に合わせた口の開き・母音を共通ランタイムへ渡す。顎には同じ開口値を使い、首・服へ顎変形を広げない。通常利用中のデモ口パクを止め、既存の呼吸/揺れ/口補正を二重適用しない。
4. 画像と描画の準備が完了してから表示を開始し、処理中は進捗を示す。毎フレームSVGを解析せず、事前に準備した描画資源を使う。
5. 同じscene・ランタイム版・時刻・入力でSVG-ThroughとSpriTalkを比較し、180コマの画像比較と発話テストで確認する。読めた・表示できただけでは完了にしない。

パッケージはZIPに素材と再生設定をまとめ、SpriTalkだけで動作させます。単体SVGの書き出しは不要ですが、現在の画質と差分処理を維持するため、内部の描画用SVGデータは許容します。ZIP内の任意JavaScriptを実行する設計にはしません。

仕様書はv0.2です。SVG-Through側は専用ZIP出力と`web/character-runtime.js`の再生アダプターを実装済みです。`web/character-package.js`に素材解決とハッシュ検証、`runtime-sources.json`に組み込むJS依存ファイルとビルド識別情報があります。正確なAPIは仕様書の第13節を参照し、SpriTalk側へ同じ版を組み込んでください。必要な機能が未対応なら、その不足を明示し、似た動きへの置換を成功扱いにしないでください。

最初の到達点は、Teth2の専用ZIPを読み込み、現在の待機動作とSpriTalkでの発話・顎の連動を確認できることです。その後、別キャラクターでも成立すること、素材保存・バックアップ復元・切り替え・負荷を検証します。既存のSimple / Layered / PachiPaku / MPNG対応は維持してください。
