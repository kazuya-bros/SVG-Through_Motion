# RIFEの8枚SVG再生の検証（2026-09-17）

以前のグリッド方式の検証は `rife-morph-verification.md`。以下は今回追加した8枚SVG方式の結果。

- JavaScript 240テスト成功。8段階の境界・単一コマ選択・従来グリッドへの切り替え・外部パッケージへの保存・素材変更の検出を含む。
- Python関連27テスト成功。目の早閉じと口の遅い開き始めの時間補正・正確な端点・不正入力・ジョブ競合/再送/中止・API契約を含む。
- 実モデルでアルファ処理追加前後のRGB出力が全ピクセル一致。透明背景に描いた緑色の図形の中央がRGBA=(0,255,0,255)、背景のアルファが0であることを確認。
- CPUモデル同梱の凍結バックエンドを使用。保存済み20パーツの実キャラクターで左右の目と口を生成した。
- UI生成後、編集APIでも口を生成し completed / applied=[mouth] を確認。
- JSON保存・読み直し後、左右の目と口すべて generated/current/enabled=true、svg_frames=8、mode=svg-frames。
- 追加データ14,295,143文字。全24コマに `<image>` はなく、ベクターとして保存される。PNG参照画像は保存しない。
- 口の確認画面に8個のSVGチャンネルが存在し、スライダー4/7で4番のコマが表示されることを確認。編集そのものは元の開閉素材を操作し、素材変更後は生成結果を無効化する。
- Canvasで0 / .25 / .5 / .75 / 1を描画し目視確認。端点の元SVGは保持するが、局所キャッシュのラスタライズ寸法が異なるため従来Canvasと全ピクセル一致ではない。
- 目と口だけのキャッシュ済み描画は120回平均約0.021ms。この値は全キャラクター・顔リグ・初回読み込みの性能を表すものではない。
- 実装UIをヘッドレスEdgeで撮影。ユーザーのTauriウィンドウの実機操作はしていない。
- 画像: `output/verification/rife-svg-sequence-20260917.png`

8枚の切り替えには段階差があり、RIFEとVTracerによる細部の変化も残る。目のコマには瞳を含むため、独立した視線移動は従来グリッド方式で使用する。詳しい条件・操作・APIは `rife-morph.md`。
